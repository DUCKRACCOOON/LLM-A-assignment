# LLM-A* 논문 리뷰

기준 문헌은 [제공받은 논문](../materials/인지개과제_논문.pdf), arXiv:2407.02511v2다. 아래 수치는 논문에 보고된 값이며 우리 실험 결과가 아니다. 과제 요건까지 포함한 기존 상세 정리는 [통합 정리](../LLM-Astar_Codex_Context.md)를 참고한다.

## 연구 문제와 방법

A*는 세밀하게 장애물을 피하며 경로를 찾지만 환경에 따라 많은 노드를 탐색한다. LLM은 전체 환경에 대한 방향을 제안할 수 있으나 좌표와 충돌을 정확히 처리하지 못한다. 논문은 LLM이 중간 안내점인 waypoint를 제안하고 A*가 실제 탐색을 수행하도록 결합한다.

기본 A*의 우선순위는 `f(n)=g(n)+h(n)`이다. LLM-A*는 `f(n)=g(n)+h(n)+d(n,t)`를 사용하며, `t`는 현재 waypoint다. 추가 거리는 실제 이동 비용 `g`가 아니라 탐색 순서를 결정하는 점수에 들어간다.

LLM이 생성한 목록은 순서 있는 안내 지점이다. 최종 goal은 변하지 않으며 각 waypoint마다 독립적인 A*를 새로 시작하지 않는다. target이 바뀌면 OPEN에 저장된 후보의 우선순위를 다시 계산한다. waypoint를 모든 최종 경로가 반드시 통과하는 것은 아니다.

논문 Algorithm 1은 이웃 좌표가 현재 target과 일치할 때 target을 전환한다. 따라서 target을 경로에 실제로 포함한 후 전환하는 알고리즘으로 이해하면 안 된다. 자세한 코드 동작은 [문답](WAYPOINT_QA.md)에 정리했다.

## 입력과 프롬프트

LLM에는 시작·목표와 수평/수직 장애물의 텍스트 표현을 준다. 이미지 입력이 핵심 실험 방식은 아니다. 수평 장애물은 `[y,x_start,x_end]`, 수직 장애물은 `[x,y_start,y_end]`다.

- Few-shot: 예시 5개.
- CoT: 추론 설명을 포함한 예시 3개.
- RePE: 점 선택·평가·수정 과정을 담은 예시 3개.

RePE의 평가 과정은 환경에서 관측 피드백을 받아 실행하는 별도 루프가 아니라 프롬프트에 담긴 모델 내부 생성 과정이다.

## 실험과 지표

논문은 50×30 크기의 100개 맵에서 각각 시작·목표 10쌍, 총 1,000개를 평가했다. 모델은 GPT-3.5와 Llama3이며 A*, Dynamic WA*, LLM-only, LLM-A*를 비교한다. Table 1은 두 고전 방법과 두 모델·세 프롬프트·두 LLM 방식의 총 14행이다.

operation, storage, 경로 길이는 사례별 A* 대비 비율의 기하평균으로 집계한다. valid path ratio는 유효한 경로를 찾은 비율이다. operation과 storage를 실제 실행시간과 메모리 바이트로 해석하지 않도록 구현을 함께 확인해야 한다.

논문 Table 1에서 Llama3 Few-shot LLM-A*는 operation ratio 44.59%, storage ratio 64.02%, relative path length 102.47%, valid path ratio 100%를 보고했다. 이는 A* 대비 operation을 44.59% 사용했다는 뜻이고 감소량은 55.41%다. 논문 일부 표현과 부록의 비율 방향 설명은 본문 4.3 및 표의 지표 정의와 일치하지 않는 부분이 있다.

## 한계와 개선 가설

- waypoint 유도 항은 admissibility를 깨뜨릴 수 있어 최단 경로를 항상 보장하지 않는다.
- waypoint의 품질과 상관없이 동일한 가중치를 적용하면 좋지 않은 안내의 영향이 커질 수 있다.
- target 전환 시 OPEN 전체를 재계산하는 비용이 발생한다.
- 높은 경로 유효성은 이 데이터에서의 실험 결과이며 모든 새 환경에서의 보장과 같지 않다.
- LLM 지연·토큰 비용과 모델/프롬프트 변화에 대한 분석을 보완할 여지가 있다.

후보인 `f=g+h+alpha_t*d(n,t)`는 waypoint 영향력 조절 방식이다. 실제 성능 우위나 최적성은 아직 검증되지 않았다. 좋은 우회 경로도 일시적으로 goal에서 멀어질 수 있으므로 단순히 목표에 가까워지는지만으로 waypoint 품질을 판단하면 안 된다.

## 재현 시 명시할 차이

현재 코드의 GPT waypoint 생성 모델은 `gpt-3.5-turbo-instruct`이고 논문 표기는 GPT-3.5-TURBO다. 공개 저장소에는 Table 1 전체 실행·집계 코드나 Dynamic WA* 구현이 없다. Dynamic WA*의 감쇠 단위·하한 및 LLM-only 실패 경로 길이 집계는 논문만으로 완전히 특정되지 않는다. 모델 대체와 구현 가정을 기록하고 논문 수치와의 차이를 분석한다.

공개 map 0의 첫 시작·목표 쌍은 프롬프트 예시와 동일하다. 원 조건 재현에서는 데이터를 유지하되 새 환경의 일반화 평가와 구분한다.
