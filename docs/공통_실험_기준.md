# 공통 실험과 결과 공유 기준

작성일: 2026-10-14. [팀 분담표](팀_개선방법_실험_분담.md)의 각 방법을 서로 비교하고 인계하기 위한 기록 기준이다. 이 문서 작성으로 새 실험을 실행한 것은 아니다.

## 같은 조건으로 비교하기

- 원 논문 재현과 개선 실험을 구분한다. 개선으로 바꾼 동작을 원본 재현 결과에 섞지 않는다.
- 입력 지도와 시작·목표, 이동 비용, 8방향 이동과 선분 장애물 충돌 규칙을 명시한다. 벽 접촉과 경계 처리도 같아야 한다.
- A*, 원 LLM-A*, 고정 g+2h 등 어떤 비교군을 사용했는지 기록한다. 고정 g+2h와 논문의 Dynamic Weighted A*는 구분한다.
- 모델 ID, 프롬프트, 생성 설정, 응답 캐시와 parser의 차이를 기록한다. gm과 sm의 서로 다른 조건에서 나온 수치만으로 우열을 정하지 않는다.
- 탐색 방법만 비교한다면 사용할 수 있는 동일 응답을 공유한다. 프롬프트·호출 방식이 다른 방법은 차이와 호출 비용을 따로 밝힌다.
- 학습·보정·설정 선택에 쓴 지도와 평가 지도를 구분한다. 같은 지도의 다른 시작·목표만 나눠 독립 지도 평가라고 표현하지 않는다.

구체적인 공통 실행 명령, 평가 문제 목록과 파일 해시는 실제 자료를 공유한 뒤 고정한다. 이 문서에서 확인되지 않은 모델 접근성이나 실험 완료 여부를 가정하지 않는다.

## 결과에 함께 남길 내용

| 구분 | 기록할 항목 |
| --- | --- |
| 구현 | 방법 ID, 담당자, 최초 구현·실험자, 브랜치, 커밋, 코드 경로 |
| 실행 | 실행 명령, 환경, 입력 문제 목록·seed, 모델·프롬프트·생성 설정 |
| 성능 | 경로 유효성, 경로 길이, operation, storage, 집계 방식과 분모 |
| 비용 | 전처리, 모든 탐색 큐, 경로 수리, 충돌 검사, 실제 시간, 모델 호출·토큰 비용 |
| 근거 | 실제 경로·평가 파일, 실패 및 악화 사례, 재현·검증 방법 |

원본 operation은 중복을 포함한 heap pop 횟수이며 실제 CPU 연산 수와 같지 않다. 여러 번 탐색하거나 여러 큐를 사용하면 전체 탐색 비용을 포함한다. 압축·전처리·거리장·학습을 사용하는 방법은 추가 작업을 숨기지 않는다.

비율의 기하평균과 산술평균, 전체 문제와 성공 문제만의 집계를 구분한다. 유효한 경로만의 길이를 제시할 때는 성공률과 해당 분모를 함께 적는다. 실패 사례를 삭제하거나 임의로 재생성한 응답으로 교체하지 않는다.

## 기실험 인계

승민의 기실험 10개 중 규민에게 2개, 준연에게 2개를 인계한다. 정확한 대응은 분담표를 따른다.

1. 최초 실험자는 실제 코드 커밋, 설정, 결과 파일과 한계를 전달한다.
2. 새 담당자는 구현 범위와 비교 조건을 확인하고 결과를 정리한다.
3. 기존 자료만으로 충분하면 불필요하게 실험을 반복하지 않는다. 누락된 비교나 검증이 있으면 보완 내용을 기록한다.
4. 최초 실험과 인계 후 검토·수정·추가 실험의 기여자를 각각 남긴다.

기실험이라는 전달 상태, 결과 파일 공유 완료, 검증 완료를 서로 구분한다. 코드나 결과가 없는 항목에 수치·경로·완료 표시를 만들어 넣지 않는다.

## main에 공유하는 방법

개인 구현과 실행 자료는 각자 브랜치에서 관리하고, 공통 문서에는 브랜치·커밋·파일 링크와 비교 가능한 요약을 남긴다. main에는 팀이 공통으로 사용할 내용을 선별해 반영한다.

보고서·구현의 최종 통합은 결과 검토 후 별도로 결정한다. API 키와 개인 기여 보고서는 공용 저장소에 올리지 않는다. 과제의 제출·평가 요건은 [안내서](<../materials/SWE3011_41 Assignment Notice (1).pdf>)를 기준으로 확인한다.
