\begin{abstract}
LLM-A*는 언어 모델이 제시한 중간 지점으로 탐색 방향을 유도하는 경로 계획 방법이다. 공개된 1,000문제에 원본 프롬프트 세 종류와 두 모델을 적용하여 논문 Table 1의 14개 조건을 재현했다. GPT-3.5 Turbo를 사용하고, 논문의 Llama3는 과제 평가 모델인 GPT-4o mini로 대체했다. 실제 응답 6,000개를 수집했으며 원본 탐색 코드와 동작을 대조했다. GPT-4o mini Few-shot의 LLM-A*는 일반 A* 대비 탐색 횟수 44.85\%, 경로 길이 102.65\%, 유효 경로 비율 100.00\%를 기록했다. 그러나 LLM 없이 목표 거리의 가중치만 두 배로 둔 $g+2h$의 탐색 횟수는 34.32\%였다. 잘못된 안내를 걸러내는 V-Gate는 원 LLM-A*보다 탐색을 줄였지만 이 대조군을 능가하지는 못했다. 이 결과를 바탕으로 waypoint 안내의 기여와 이번 재현의 한계를 분석한다.
\end{abstract}

\section{재현 목적과 범위}
\citet{meng2025}의 LLM-A*는 LLM이 생성한 waypoint와 A* 탐색을 결합한다. 제시된 좌표를 그대로 따라가는 대신 그 좌표와의 거리를 탐색 우선순위에 반영한다. 최종 목적지는 고정되어 있고 waypoint는 반드시 방문해야 하는 지점이 아니다.

Table 1의 주요 비교를 재현한 뒤 원 방법의 한계를 찾아 개선안을 구현하고 평가했다. 원 알고리즘 및 공식 코드와 이번에 추가한 실험 실행기, 입력 어댑터, 검증 절차, V-Gate를 구분했다. 논문의 모든 실험을 반복한 것은 아니다. Table 1을 중심으로 진행했으며 논문의 10단계 크기 확장 실험은 수행하지 않았다.

공개 데이터의 맵 100개와 맵마다 주어진 출발점--목적지 10쌍을 모두 사용했다. 명목 크기는 $50\times30$이다. 데이터에는 상한을 포함하지 않는 범위 $[0,51]$, $[0,31]$로 저장되어 외곽 벽은 50과 30에 위치한다. 장애물은 수평 또는 수직 선분이다. 탐색은 원본과 같은 8방향 이동과 유클리드 이동 비용을 사용한다.

\section{원 방법과 구현 검증}
최종 목적지를 $G$, 현재 안내 지점을 $T$라 하면 공개된 구현은 다음 점수가 작은 후보부터 탐색한다.
\begin{equation}
 f(n)=g(n)+\|n-G\|_2+\|n-T\|_2.
\end{equation}
$g(n)$은 출발점에서 현재 후보까지의 누적 비용이다. 뒤의 두 항은 각각 최종 목적지와 현재 waypoint까지의 거리이다.

원본은 생성한 이웃 좌표가 $T$와 같으면 충돌 및 CLOSED 검사 전에 안내 지점을 갱신하고 OPEN의 우선순위를 다시 계산한다. CLOSED에 들어간 노드는 다시 열지 않지만 큐에서 중복으로 꺼낸 항목도 탐색 횟수에 포함한다. 저장량은 비용 사전 $g$의 항목 수이며 무한 비용 항목도 포함한다. waypoint의 경계 필터와 장애물 끝점 필터도 원본 동작을 유지했다.

반복 실험을 위해 충돌 결과를 캐시하고 CLOSED 소속 검사에 집합을 사용했다. 탐색 순서와 중복 처리는 바꾸지 않았다. 미리 정한 30문제의 90회 탐색을 원본과 비교하여 경로, 탐색 횟수, 저장량과 길이의 일치를 확인했다. 연속 선분 3,000개의 충돌 판정도 Shapely와 대조했다. 최종 검사에서는 A* 전체 1,000개의 길이를 독립 Dijkstra 구현과 비교하고 모든 성공 경로를 다시 검사했다. 실제 모델 응답 62개도 수정하지 않은 원본 탐색 코드에 넣어 경로와 지표가 일치하는지 확인했다. 동일 출발점ㆍ목적지와 도달 불가능한 입력에 구조화된 결과를 반환하고 입력 사전을 직접 바꾸지 않는 부분은 원본과의 차이로 기록했다.

\paragraph{Dynamic Weighted A*의 구현 가정.}
논문에는 초기 가중치 2와 감쇠율 0.99가 제시되어 있지만 저장소에 해당 구현이 없다. 목표가 아닌 노드를 꺼낼 때마다 가중치를 0.99배로 줄이되 하한을 1로 두고 OPEN을 다시 정렬했다. 탐색 횟수, 저장량, 길이는 각각 59.27\%, 78.52\%, 100.24\%였다. 논문의 60.91\%, 78.53\%, 100.24\%와 비슷하지만 이것만으로 구현까지 같다고 판단하지 않는다.

\section{실험 설정과 평가 지표}
모델은 \texttt{gpt-4o-mini-2024-07-18}과 \texttt{gpt-3.5-turbo-0125}이다. 과제에서 접근 가능한 LLM을 허용하고 GPT-4o mini를 주 평가 모델로 지정했으므로 이를 포함했다. Llama3는 실행하지 않았으며 GPT-3.5 역시 원 실험과 동일한 버전이라고 주장하지 않는다. 원 코드의 Llama3는 Meta-Llama-3-8B-Instruct를 bfloat16으로 사용하고 전용 프롬프트와 8,000토큰 생성 상한을 적용한다. 이 조건을 추가해야 원 논문의 두 모델을 모두 다룰 수 있다. GPT-4o mini 결과를 Llama3의 재현 결과로 해석하지 않는다.

원본 Few-shot, CoT, RePE 프롬프트를 그대로 사용했다. 예시는 각각 5개, 3개, 3개이다. RePE는 한 번의 프롬프트에서 경로 평가를 요구하며 별도의 반복 피드백 루프를 만들지 않았다. 전체 프롬프트를 Chat Completions의 사용자 메시지 하나로 전달하고 temperature는 0, 출력 상한은 1,000토큰으로 설정했다. 원 코드의 instruct Completion API와 줄바꿈 종료 조건은 그대로 쓰지 않았다. 여러 줄의 응답을 받도록 종료 조건을 제거했으며 이 차이를 결과 비교 시 고려한다.

파일럿은 맵 번호 0,10,$\ldots$,90의 앞 세 문제씩, 총 30문제로 진행했다. 생성 설정이 바뀌지 않아 파일럿의 180개 응답도 본 실험 6,000개에 포함했다. 한 응답을 LLM-only와 LLM-A* 평가에 함께 사용했다. 경로가 잘못 나왔다는 이유로 다시 요청하거나 좌표를 보정하지 않았다. API 요청 6,000건은 모두 응답을 받았으며, 그중 229건은 토큰 상한에서 종료되었다. API 호출 성공과 유효한 경로 생성은 구분했다. 요청과 응답 원문, 모델 ID, 토큰 수, 종료 사유, 시각과 파일 해시를 저장했다. 인증 정보는 제출물에서 제외했다.

\subsection{비율의 계산과 성공 기준}
각 문제의 측정값을 같은 문제에서 일반 A*의 값으로 나눈 뒤 기하평균을 계산했다. 지표 $m$의 보고 값은 다음과 같다.
\begin{equation}
100\exp\left(\frac{1}{N}\sum_{i=1}^{N}\log\frac{m_i}{m_i^{A*}}\right).
\end{equation}
탐색 횟수, 저장량과 길이는 낮을수록 좋다. 예를 들어 40\%는 이 집계 방식에서 기준의 40\%를 사용했다는 뜻이며 전체 실행 시간이 40\%가 되었다는 뜻은 아니다. 탐색 횟수는 큐에서 꺼낸 횟수이지 CPU 명령어 수가 아니고, 저장량도 메모리 바이트 수가 아니다.

유효 경로는 지정된 출발점과 목적지를 연결하고 경계 안에 있으며 장애물과 충돌하지 않는 경로이다. 탐색 경로에는 8방향 이동 조건도 검사했다. 성공률의 분모는 항상 1,000이다.

LLM-only는 출력 좌표를 연결한 선분 경로를 그대로 평가했다. 탐색으로 수리하지 않았으므로 탐색 횟수와 저장량은 보고하지 않는다. 논문은 실패 경로의 길이 집계를 충분히 설명하지 않는다. 이번에는 유효 경로의 길이만 집계하고 표본 수를 표시했다. 서로 다른 성공 부분집합의 길이를 공정한 전체 성능 비교로 해석해서는 안 된다. 여섯 LLM-only 조건에서 모두 성공한 공통 문제는 없었다. 연속 선분의 길이는 8방향 격자의 최단 길이보다 짧을 수도 있으므로 두 이동 모델의 최적성을 혼동하지 않는다.

\section{재현 결과와 논문과의 차이}
표~\ref{tab:reproduction}은 문제별 저장 기록에서 생성했다. 여섯 LLM-A* 조건의 탐색 횟수는 일반 A*의 40.41\%에서 72.49\% 사이였다. GPT-3.5 Few-shot에서는 탐색 횟수 40.41\%, 저장량 61.34\%, 길이 102.26\%를 기록했다. 원 논문의 GPT-3.5 Few-shot LLM-A*는 탐색 횟수 57.39\%, 저장량 74.96\%, 길이 102.44\%, 유효 경로 100\%였다. 수치는 다르지만 일반 A*보다 탐색을 줄이고 경로가 조금 길어지는 경향은 같았다. 모델 버전, API와 종료 조건, 파싱 및 평가 규칙의 차이가 영향을 줄 수 있으나 어느 요인이 얼마만큼 영향을 주었는지는 분리 실험을 하지 않아 알 수 없다.

두 숫자의 좌표를 요구하는 파서에서는 32개 응답의 좌표 형식이 맞지 않았고, 382개에서는 읽을 수 있는 목록을 찾지 못했다. LLM-only의 유효 경로 비율은 5.60\%에서 12.10\%였다. 반면 LLM-A*는 이 데이터에서 모두 유효한 경로를 찾았다. 원본은 좌표 목록이 없으면 출발점과 목적지를 대신 사용한다. 이때 $T=G$이므로 점수는 $g+2h_G$이다. 일반 A*로 돌아가는 것이 아니다. 숫자가 세 개 이상인 항목은 앞의 두 숫자를 사용하므로 출력 마지막에 반복된 장애물 목록도 waypoint로 해석될 수 있다. 재현에서는 이 동작을 유지하되 오류 여부를 따로 기록했다. LLM-only와 개선안은 두 숫자의 좌표를 요구한다. LLM-A*의 성공률 100\%가 LLM 출력의 정확도 100\%를 뜻하지 않는 이유이다.

\subsection{LLM 없는 대조군이 필요한 이유}
LLM의 기여를 따로 확인하려고 같은 탐색 코드에서 $T$를 $G$로 고정했다. LLM을 호출하지 않으며 점수는 $g+2h_G$이다. 탐색 횟수 34.32\%, 저장량 56.23\%, 길이 102.02\%, 유효 경로 100\%를 기록했다. 여섯 LLM-A* 조건 모두 이 대조군보다 집계 탐색 횟수가 많았다. 다만 모든 개별 문제에서 대조군이 이겼다는 뜻은 아니다. 일반 A*보다 탐색을 줄였다는 사실만으로 그 효과를 LLM 안내의 기여라고 단정하기 어렵다.

이 대조군은 논문 Table 1의 Dynamic Weighted A*와 다르다. Dynamic Weighted A*는 가중치가 줄어들지만 고정 $g+2h$는 끝까지 2를 유지한다. 이번 결과는 논문에 없던 비교 조건에서 확인한 추가 관측이다. 잘못된 waypoint가 불필요한 탐색을 유도할 수 있지만 이것만으로 전체 차이의 원인을 확정하지 않는다. 고정 가중치도 최단 경로를 보장하지 않으며 이번 결과를 모든 맵과 LLM 안내 방식에 일반화할 수 없다.

\section{개선안: 유효성 검사 후 안내 선택}
파일럿에서 충돌하는 선분 경로와 잘못된 좌표 형식이 관찰되었다. 이를 바탕으로 V-Gate를 구현했다. 생성 경로의 출발점과 목적지가 맞고 경계와 충돌 검사를 통과하며 모든 좌표가 정수일 때만 원래 LLM-A* 안내를 사용한다. 하나라도 실패하면 $g+2h_G$로 탐색한다. 모든 맵에 같은 규칙을 적용하며 개별 맵의 성능을 보고 규칙을 바꾸지 않았다.

\begin{enumerate}
\item 원본 프롬프트로 한 번 생성하고 좌표를 읽는다.
\item 전체 선분 경로와 정수 좌표 조건을 검사한다.
\item 통과하면 LLM-A*, 실패하면 $g+2h_G$로 탐색한다.
\item 반환 경로의 유효성과 탐색 지표를 기록한다.
\end{enumerate}

유효한 경로도 길거나 탐색에 도움이 되지 않을 수 있다. 반대로 충돌하는 경로 안에도 유용한 중간 지점이 있을 수 있다. 그러므로 이 검사는 안내의 품질을 보장하는 규칙이 아니라 실험으로 확인할 가설이다. 잘못된 출력에 대한 예외 처리는 추가했지만 새로운 최적성 정리를 주장하지 않는다.

추가 확인에서 원 LLM-A*보다 탐색 횟수가 줄어든 문제는 530개, 같은 문제는 272개, 늘어난 문제는 198개였다. 파일럿에 사용한 맵 전체를 제외한 900문제에서도 탐색 횟수 비율은 77.66\%였다. 이는 저장된 공개 결과의 사후 부분집합 분석이며 새로 수집한 비공개 시험 결과는 아니다.

V-Gate가 원 LLM-A*보다 좋아졌다는 점은 확인했지만 LLM 없는 대조군을 능가했다는 근거는 없다. 안내를 대부분 거부했으므로 개선의 상당 부분이 가중 탐색으로 전환한 데서 나왔을 가능성이 있다. 구성 요소 실험에서도 공간 검사를 제거하면 원 LLM-A*와 비슷해지고, 실패 시 일반 A*를 쓰면 탐색량이 크게 증가했다. 거부할 응답도 먼저 생성하므로 API 비용은 없어지지 않는다.

\section{새 맵, 비용 및 개별 사례}
난수 시드 20261013으로 새 맵 10개를 만들고 각 맵에서 도달 가능한 세 문제를 선택했다. 수평ㆍ수직 장애물은 각각 네 개이며 크기는 $32\times22$, $52\times32$, $72\times42$를 번갈아 적용했다. Dijkstra로 도달 가능성과 기준 길이를 확인한 뒤 GPT-4o mini Few-shot으로 30개 응답을 새로 받았다. LLM-A*와 V-Gate는 모두 30문제에 성공했으며 탐색 횟수 비율은 각각 42.12\%, 33.39\%였다. LLM 없는 대조군은 30.51\%였고 LLM-only는 9/30문제에 성공했다. 새 입력에서 실행되는지 확인하는 소규모 검사이며 숨겨진 평가 환경 전체를 대표하지 않는다. 원본 프롬프트에는 경계 크기가 직접 포함되지 않아 크기가 다른 맵에서 한계가 있을 수 있다.

본 실험은 입력 4,730,480토큰과 출력 2,031,098토큰을 사용했다. 표준 요금 추산은 미화 3.104달러이다. 평균 요청 지연은 GPT-3.5 1.81초, GPT-4o mini 4.85초였다. 비용은 모델 문서의 표준 토큰 요금으로 추산했으며 실제 청구액은 아니다\citep{openai_mini,openai_gpt35}. 모델 접근 확인, 자연어 입력 확인과 새 맵 30회는 본 실험 비용에서 제외했다. 요청 지연에는 네트워크와 서비스 대기가 포함된다. 저장 응답으로 탐색만 다시 실행하는 시간과 처음부터 LLM을 호출하는 시간을 구분했다. 최적화한 실행기의 CPU 시간을 원본 프로그램과의 속도 개선 근거로 사용하지 않았다.

프롬프트 예시와 문제의 모든 입력 필드가 일치하는 경우는 Few-shot 5개, CoT 3개, RePE 3개였다. 주 표는 전체 데이터를 유지하고 이 문제들을 제외한 집계도 별도로 저장했다. 예시와 겹치는 공개 데이터를 독립 시험 데이터라고 부르지 않았다. 그림~\ref{fig:cases}에는 GPT-4o mini Few-shot에서 LLM-A*와 $g+2h$의 탐색 횟수 비율이 중앙값인 사례와 가장 큰 사례를 표시했다. 동률은 문제 ID 순으로 정했다. 전체 성능은 모든 문제로 계산했으며 두 사례는 설명용이다. 출력 원문과 실제 경로를 저장하여 waypoint와 실제 방문한 좌표를 구분할 수 있게 했다.

\section{한계와 재현 방법}
모델ㆍ프롬프트ㆍ문제마다 생성은 한 번씩이다. temperature 0도 반복 응답이 항상 같음을 보장하지 않는다. 원 논문의 Llama3가 빠졌으며 Dynamic Weighted A*의 해석, 파서, 출력 상한과 실패 경로의 길이 집계도 수치 비교의 한계이다. V-Gate는 공개 데이터의 파일럿을 바탕으로 정했으므로 독립된 비공개 시험 결과로 볼 수 없다. 새 맵은 표본이 작고 장애물 유형이 제한되어 있다. 숨겨진 환경의 점수나 다른 팀과의 순위는 이번 결과로 알 수 없다.

코드에는 의존성 목록, README 실행 안내, 수정하지 않은 원본, 응답 원문과 문제별 결과를 포함한다. \texttt{python -m reproduction.verify}로 원본 대조 검사를 실행할 수 있다. 저장 응답으로 표를 재계산할 때는 API 키가 필요 없다. 모델은 실행 시 지정한다. 원본 형식의 사전 입력과 자연어 입력을 지원하되 자연어를 사전으로 바꾸는 추가 호출은 Table 1 실험에 섞지 않았다. 출처와 구현 차이는 \texttt{reproduction/AUDIT.md}에 기록했다.

\section{AI 도구 사용 범위}
