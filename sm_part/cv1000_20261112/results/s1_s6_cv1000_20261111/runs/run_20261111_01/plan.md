# S1~S6 공개 1,000문제 실험 계획

작성: 2026-11-11, Asia/Seoul. 상태: 계획 수립 완료, 실험 미실행.
사용자 선택: 기존 GM 공개 1,000문제, 지도 단위 교차검증으로 학습 중복 방지.

## 1. 목표와 기존 실험과의 차이

목표는 성공률과 각 방법의 경로 품질 조건을 함께 확인하면서 동일 문제의 원 LLM-A* 대비 시간·탐색량·비용이 얼마나 개선되는지 평가하는 것이다.

1,000문제는 **100개 지도 × 지도당 시작·목표 10쌍**이다. 1,000개 독립 지도라는 뜻이 아니다.
2026-10-28 SM 실행도 공개 전체 1,000문제를 실행했으나 S4 학습·S6 설정 선택에 사용한 문제가 포함돼 독립 평가 표는 200문제였다. 이번에는 모든 문제에 대해 자기 지도를 사용하지 않은 학습·선택 결과로 평가하는 out-of-fold(OOF) 결과 1,000개를 얻는다.

공통 주 분모는 **원 LLM-A***다. 과거 계획의 g+2h 주 분모를 변경하며 g+2h·정확 A*·K3와의 비교도 보조로 남긴다. 공개 자료가 이미 과거 연구에서 관찰됐다는 사실은 교차검증으로 없어지지 않는다. 연구 전체의 완전한 미관측 테스트라고 주장하지 않는다.

## 2. 데이터 분할

| 구분 | 지도 수 / 문제 수 | 역할 |
| --- | --- | --- |
| 전체 | 100 / 1,000 | 기존 GM 실제 입력·ID·이동·충돌 조건 유지 |
| 외부 평가 fold | 20 / 200 | 각 fold의 성능 평가 전용 |
| 내부 학습 | 64 / 640 | S4 학습, S6 후보 1차 평가 |
| 내부 검증 | 16 / 160 | S4 checkpoint 선택, S6 최종 후보 선택 |
| 5개 fold의 OOF 합계 | 100 / 1,000 | 각 문제를 정확히 한 번 평가 |

- 지도 ID를 정렬하고 `random.Random(20261111)`로 섞어 20지도씩 5개 외부 fold를 만든다. 나머지 80지도는 fold별 `20261111 + fold_id`로 섞어 64/16으로 나눈다. fold_id는 0~4다.
- 같은 지도의 10문제는 항상 같은 분할에 속한다. 장애물 순서에 독립적인 지도 해시로 중복 기하도 검사한다. 중복 지도가 있으면 같은 그룹으로 묶고, 동일한 20지도 분할이 불가능하면 실행 전에 분할표와 실제 크기를 수정해 기록한다.
- 평가 지도의 정답·탐색량·시간·모델 출력으로 checkpoint, S6 후보, trigger, 파서 규칙을 선택하지 않는다.
- 다섯 fold의 모델과 S6 설정을 모두 고정한 뒤 외부 평가를 진행한다. 먼저 평가한 fold를 보고 뒤 fold의 설정을 바꾸지 않는다.
- S4의 정규화·클래스 가중치 등 학습 통계도 해당 fold의 내부 학습 자료로만 계산한다.

계획 작성 중 실제 입력을 읽어 [지도별 분할 명단](fold_manifest.json)을 생성했다. 고유 지도 기하 100개, 각 fold 640/160/200문제, 평가 문제 합집합 1,000개 및 fold 내부 지도 중복 0을 확인했다. 이는 데이터 분할 검사이며 학습·성능 실험 결과가 아니다.

## 3. Few-shot 예시의 지도 중복 통제

GM standard 프롬프트에는 공개 데이터와 겹치는 지도 예시가 포함되어 있다. 공개 100지도를 모두 평가하면서 이 예시를 그대로 쓰면 일부 평가 지도는 프롬프트에도 나타난다.

이번 계획은 **공개 100지도와 기하가 중복되지 않는 별도 예시 지도 5개**를 준비해 모든 fold에서 동일하게 사용한다. GM의 지시문·출력 형식·예시 개수는 유지하고 예시 입력·경로만 바꾼다. 예시 지도 seed는 20261112, 문제별 정답 경로를 독립 검증한 뒤 결정적 충돌 없는 단축으로 예시 경유점을 만든다. 예시 5개와 경로는 평가 실행 전에 고정한다.

이는 GM 원문 프롬프트의 바이트 단위 재현과 다른 통제 변경이다. 원 LLM-A*와 S1~S3에 같은 변경을 적용하고 요청 해시·예시 출처·토큰 수를 기록한다. 원 LLM-A*라는 이름은 원 탐색 알고리즘을 뜻한다. 예시 5개는 성능 평가 1,000문제에 합산하지 않는다.

## 4. 환경·고정 파라미터

- 한 Windows PC, Python **3.11.18** 격리 환경을 기준으로 준비한다. 실제 CPU·OS·패키지·전원 상태를 실행 manifest에 남긴다.
- 기존 검증 환경의 NumPy 1.26.4, SciPy 1.15.3, Shapely 2.2.0, PyTorch 2.7.1+cpu를 기준으로 재현성을 확인한다. 변경하면 이유와 정확한 버전을 기록한다.
- LLM 예정 ID: `gpt-4o-mini-2024-07-18`, temperature=0, max_tokens=1000, 줄바꿈 stop 없음. 실행 전 접근성을 확인한다. 현재 사용 가능하다고 미리 단정하거나 다른 모델로 자동 교체하지 않는다.
- 입력의 8방향 이동, 축 비용 1·대각 √2, GM의 경계·벽 접촉·퇴화 선분 규칙을 유지한다.
- 평가 시 CPU/native thread=1, S4 학습은 4스레드. 학습·API 수집과 시간 계측을 동시에 수행하지 않는다.
- 매 질의 전처리를 포함하는 단일 질의를 주 조건으로 삼는다. 지도별 캐시 재사용 성능은 이번 주 실험에 섞지 않는다. 모델 로딩·warm-up은 별도 기록한다.

## 5. 방법별 개입과 직접 대조

| 방법 | 실행 조건 | 효과 분리를 위한 대조 |
| --- | --- | --- |
| S1 | 중복·왕복 제거, 충돌 없는 단축, 유효성 검사 | 같은 정규화·검증만 적용한 V-Gate-only |
| S2 | 최초 무효 제안에 구체 오류를 주고 한 번 수정 | 같은 호출 기회의 일반 재검토, 최초 응답 원 LLM-A* |
| S3 | g+2h로 시작, 정체 시 최대 한 번 안내 삽입, 탐색 상태 유지 | 즉시 안내 원 LLM-A*, 끝까지 무안내 g+2h |
| S4 | fold별 3개 시드로 재학습한 경로 확률, FOCAL w=1.05 | 같은 FOCAL 무안내, 학습 전 모델 |
| S5 | sparse 직사각형 압축, 정확 탐색, 격자 경로 복원 | 동일 백엔드 A*_octile |
| S6 | 일부 벽으로 정확 풀이, 전체 벽 검사, 충돌 벽 추가, 최대 4회/전체 벽 fallback | rule, 같은 초기 벽 수의 random, 전체 벽 A*_octile |

S3는 `max(10, ceil(d0))` pop마다 검사하고 최소 목표 거리 개선이 `0.05*d0` 미만이면 호출하는 기존 규칙을 고정한다. 호출 전후 상태·pop·확장·OPEN 재계산 비용을 모두 기록한다.

S4는 160,297 파라미터 소형 모델, AdamW lr=0.001, weight_decay=0.0001, batch=32, 최대 60 epochs, seed=11/22/33을 유지한다. 내부 검증 손실로 checkpoint를 선택하고 매 fold 처음부터 학습한다. **5 folds × 3 seeds = 15개 모델**이다. 과거 checkpoint는 외부 평가에 재사용하지 않는다. 시드별 결과와 문제별 시드 평균을 모두 보고하며 시드를 독립 문제로 세지 않는다.

S6는 fold당 새 LLM 가중치 후보 최대 12개를 생성한다. 평가 지도의 정보는 프롬프트에 넣지 않는다. 네 특징과 [-2,2] 유한 계수 제약을 유지한다. 단일 JSON 코드블록 제거를 허용하는 파서 규칙을 사전에 고정한다. 내부 학습의 A*_octile 대비 pop 기하평균으로 상위 3개를 고르고 내부 검증에서 한 개를 선택한다. 동률은 후보 번호로 결정한다. 평가 fold를 보고 좋은 후보를 다시 생성하지 않는다. 후보가 모두 무효면 그 사실을 실패로 기록하고 rule 대조를 주 S6로 바꿔 부르지 않는다.

과거 `[1.5,1.0,0.5,-1.0]` 설정은 일부 공개 지도로 선택됐으므로 모든 fold의 독립 평가에 그대로 사용하지 않는다. 과거 `[0.5,0.3,0.1,0.1]`도 역사적 보조 조건으로만 표시한다.

## 6. 조건 수와 반복

기존 실행의 22개 조건을 유지한다.

`A_GM`, `N_g2h`, `B_llm`, `V_GATE_GM`, `V_GATE_NORMALIZED`,
`S1`, `S2_feedback`, `S2_control`, `S3`,
`K3_wall_euclidean`, `K3_wall_octile`, `A_OCT`, `FOCAL_105`,
`S5`, `S6_rule`, `S6_random`, `S6_program`, `S6_historical`,
`S4_seed11`, `S4_seed22`, `S4_seed33`, `S4_untrained`.

`S6_historical`은 기존 자료 노출이 있는 참고 조건으로 현재 후보의 독립 일반화 순위에서 제외한다. `S4_mean`은 세 시드의 사후 집계이며 23번째 실행 조건이 아니다.

- 주 평가: **1,000문제 × 22조건 × 5회 = 110,000회** 계획기 계측.
- 각 문제에서 모든 방법을 순차 실행하되 매 반복 순서를 고정 난수로 섞는다. fold별 독립 실행 블록에도 같은 대조군을 포함한다.
- 문제별 시간은 5회 중앙값. 같은 응답을 쓴 5회는 LLM 생성 반복이 아니다.
- 고유 평가 문제는 1,000개다. 내부 학습·S6 후보 평가·파일럿·메모리 측정 횟수를 여기에 더하지 않는다.
- S6 random과 S4 untrained의 난수는 fold·문제·시드로 고정한다. 주 random 대조는 고정 정책의 한 실현이며 난수 분산 전체를 대표한다고 주장하지 않는다.

## 7. 새 응답과 예산

- 외부 평가 1,000문제의 최초 응답을 새로 생성하고 B/S1/S2/S3/관련 gate 조건이 공유한다.
- 최초 무효 응답 수를 I라 하면 일반 재검토 I건, 구체 피드백 I건을 각각 생성한다. 최대 추가 호출은 2,000건이다.
- S6의 오프라인 후보는 5 folds × 12 = 최대 60건이다.
- 예정 상한: **1,000 + 2I + 60 ≤ 3,060개 생성 요청**. 오류 전송·접근성 점검 등은 별도 기록하고 합계를 숨기지 않는다.
- 자동 전송 재시도는 기본 0회. 장애 발생 시 이미 성공한 응답을 고정하고 해당 요청의 상태를 기록한 뒤 재개한다. 무효 경로나 토큰 제한 종료를 이유로 좋은 답이 나올 때까지 재생성하지 않는다.
- 요청·응답 본문, 모델 ID, usage, 대기시간, finish_reason, 요청 해시와 응답 해시를 서로 다른 필드로 저장한다.
- 수집한 총요청 수와 방법을 단독 사용할 때의 논리 호출 수를 구분한다. S3가 호출하지 않은 문제라도 B를 위해 공통 응답은 수집된다.
- 금액·총소요시간은 개발용 파일럿의 실제 토큰·지연과 실행 당시 단가를 확인한 뒤 산출한다. 현재 계획에 임의 금액이나 확정 시간을 적지 않는다.

## 8. 평가 지표와 판정

| 지표 | 정의·보고 방식 |
| --- | --- |
| 총응답시간 | 공유 수집의 API 대기＋계획기 시간인 재구성 추정치, 원 LLM-A* 대비 비율과 평균 초를 함께 보고 |
| 계획기 시간 | 파싱·수리·전처리·추론·모든 탐색/재탐색·필수 검증·복원 포함 |
| 탐색량 | 모든 heap pop과 실제 이웃 확장을 별도로 계측, 준비/검색/재탐색 구분 |
| 관리 작업 | push, stale, heapify/rekey, FOCAL 스캔, 충돌 검사, fallback |
| 경로 품질 | L/L*, L/L_B, 최단 일치율, P95·최대 초과율, 5%/10% 초과 건수 |
| 성공률 | 전체 1,000문제 중 유효 최종 경로 비율, 모델 제안 유효율과 별도 |
| 메모리 | 최대 OPEN, 상태 수, 전처리 구조·모델 크기; 별도 프로세스 RSS 표본 peak |
| LLM 비용 | 논리 호출, 실제 수집, 입출력 토큰, 재시도·대기, S6 오프라인 제안 비용 |

총응답시간은 독립 온라인 서비스 반복 실측이라고 표시하지 않는다. 공유 응답을 통한 통제와 서비스 지연 검증은 다른 실험이다. 실제 온라인 종단 간 지연이 필요하면 별도 예산·사전 규약의 후속 실험으로 설계한다.

메모리 보조 측정은 사전 고정한 20지도×1문제에서 조건별 새 프로세스 3회로 수행한다. nominal 1ms RSS 표본에는 Python·라이브러리·모델 상주분이 포함됨을 밝히고 baseline RSS와 증가량도 남긴다. 시간 주 계측과 동시 수행하지 않으며 순간 peak나 순수 할당량으로 표현하지 않는다.

카운터가 없는 엔진을 노드 확장 수로 대신 채우지 않는다. heap 함수 호출과 배열 선택/스캔을 별도 계측한다. 계측 비용은 모든 비교군에 같은 정책으로 적용한다. 계측 자체가 미치는 영향은 개발 자료에서 확인한다.

OOF 1,000문제의 대응 양수 비율 기하평균과 `100×(1−비율)` 개선율, 개선/동일/악화 건수를 보고한다. 호출 0을 1로 치환하지 않으며 호출·토큰은 합계·산술평균으로 비교한다. 산술평균 시간도 함께 공개해 조건부 무호출이 기하평균에 미치는 영향을 설명한다.

지도 단위 bootstrap 2,000회, 95% 구간을 산출한다. fold 안에서 지도를 재표집해 fold 구성을 유지하고 fold별 결과도 따로 제시한다. 이는 고정된 학습 모델·응답에 조건부인 탐색적 구간이며 CV 재분할·재학습·API 반복의 전체 불확실성을 포괄하지 않는다. 여섯 방법의 주 시간 비교를 확증적으로 선언하면 다중 비교를 고려한 보수적 구간도 함께 제시한다.

S4는 L≤1.05L*, S5/S6는 L=L*를 검증한다. S1~S3에는 동일 상한 보장이 없으므로 같은 품질 제약의 단일 순위를 주장하지 않는다. 실패와 timeout은 삭제하지 않고 전체 분모·소모 비용에 남긴다. 양쪽 성공 경로만의 길이 비교에는 해당 분모를 명시한다. timeout은 검열값으로 보고하고 성공 사례 시간만으로 승자를 고르지 않는다.
