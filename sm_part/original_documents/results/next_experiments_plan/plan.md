# LLM-A* 추가 개선 실험 계획

작성일 2026년 10월 14일 · 계획 버전 `next-search-20261014-v1` · 상태 **구현 전 계획**

이번 실험의 목표는 **경로 길이를 보장하면서 실제 계산 비용을 줄이는 것**이다. 앞서 제안한 세 후보를 공간 압축, 장애물의 단계적 반영, 위상 기반 안내 순서로 검증한다. 먼저 앞의 두 후보로 정확한 최단 경로 탐색을 개선하고, 세 번째 후보에서 LLM의 독립적인 기여를 확인한다. 후보를 처음부터 모두 결합하지 않는다.

이 문서의 감소율 기준은 **채택 목표**이며 예상 성능이 아니다. 현재 완료된 작업은 계획 수립이며, 새 알고리즘 구현·데이터 생성·모델 추론·실험 실행은 포함하지 않는다. 설정 요약은 [protocol.json](C:/인지개/results/next_experiments_plan/protocol.json)에 있다. 실제 실행 전에는 구현 해시와 검증 결과를 추가해 별도의 고정 프로토콜을 만든다.

## 3 공통 탐색 문제와 기준 구현

**문제 정의를 유지한다.** 정수 좌표의 8방향 이동, 직선 한 칸 비용 1, 대각선 한 칸 비용 √2, 기존 외곽 경계 및 선분 충돌 판정을 사용한다. 벽 끝점 접촉·대각선 교차·길이 0인 벽의 기존 처리도 차등 검증한다. 연속 공간의 지름길이나 any-angle 경로를 반환해 길이를 줄인 것으로 비교하지 않는다.

새 기준 휴리스틱은 `h = max(dx,dy) + (√2−1) min(dx,dy)`인 octile 거리다. 기존 `core.py`, `improve_core.py`, `candidate_core.py`와 완료 결과는 보존하고, 새 구현은 별도 모듈에 둔다.

| 비교군 ID | 정의와 역할 |
| --- | --- |
| A_OCT | 효율적인 heap 기반 A*, octile, 더 좋은 g 발견 시 갱신 및 필요 시 재개방; 정확한 주 기준 |
| N_LEGACY | 원래 N의 `g+2h_euclidean`와 중복 pop 등 재현 규칙 유지; 과거 결과 연결 |
| N_CLEAN | 같은 `g+2h_euclidean`을 새 공통 탐색기에 구현; 안내 방식과 구현 차이를 분리 |
| WA_101 / WA_102 / WA_200 | octile Weighted A*, 가중치 1.01 / 1.02 / 2; 속도와 길이의 교환관계 비교 |
| FOCAL_101 / FOCAL_102 | octile anchor와 기본 거리 보조 순위를 쓰는 FOCAL; R3의 직접 대조군 |

개발 단계에서 Euclidean A*도 한 번 비교해 octile 변경의 효과를 분리한다. R3의 w=1에서는 동일한 동점 규칙을 쓰는 A_OCT가 기본 안내 대조군 역할을 한다. w=1.1은 과거 후보 결과를 연결하는 보조 실험에만 사용한다.

현재 `candidate_core.focal`은 매 단계 OPEN 배열 생성 및 일부 모드에서 정렬을 수행한다. 이를 빠른 A*/Weighted A*의 기준 구현으로 그대로 사용하지 않는다. 새 FOCAL은 anchor 최소값과 보조 큐를 유지하고, g 변경·자격 범위 변경·오래된 항목 처리를 검증한다. 필요한 FOCAL 자격 갱신 비용도 계측한다. 공통 동점 규칙은 `(f, h, 좌표 ID)`로 고정하고, 보조 안내가 바꾸는 순위만 후보 차이로 둔다.

단일 질의 A_OCT에는 필요할 때 이웃의 충돌을 검사하는 구현을 기본으로 둔다. 모든 방법에 전체 격자 그래프를 미리 만들도록 강제하지 않는다. 전체 그래프 전처리를 쓰는 변형은 비용을 포함해 개발·검증 데이터에서 비교한다. 동일 자료구조를 사용하는 비교는 알고리즘 원인 분석용으로, 각 방법의 고정된 효율적 구현끼리의 비교는 실제 성능 평가용으로 구분한다.

## 4 R1 정확한 공간 압축 실험

### 구현과 정확성 조건

1. 원래 격자에서 내부 이동이 모두 유효한 직사각형 영역을 찾는다. 장애물의 위치뿐 아니라 **간선의 유효성**을 기준으로 인증한다.
2. 첫 구현은 영역의 경계 정점을 모두 유지하고 내부 정점만 생략한다. 영역 간 원래 이동 간선은 유지한다.
3. 같은 영역의 경계 정점 사이를 정확한 octile 비용의 macro edge로 연결한다. 시작·목표가 내부에 있으면 임시 정점으로 삽입한다.
4. macro edge를 원래의 유효한 단위 이동 경로로 복원한다. 복원 길이가 저장 비용과 같아야 한다.
5. 보수적인 구현이 통과한 뒤 RSR의 불필요한 macro edge 제거 규칙을 적용한다. 벽 끝점 몇 개만 남기는 압축은 별도 보존 증명 없이는 사용하지 않는다.

정확성의 핵심은 두 방향이다. 압축 경로는 같은 비용의 원래 경로로 복원되어야 하고, 원래 최단 경로의 각 영역 통과는 더 비싸지 않은 압축 경로로 대체되어야 한다. 두 조건으로 최적 길이의 동등성을 보인다. 테스트 통과와 이 보존 논증을 모두 요구한다.

[RSR 연구](https://www.harabor.net/data/papers/harabor-botea-kilby-sara11.pdf)는 빈 직사각형과 macro edge를 이용한 최적성 보존의 출발점이다. [Subgoal Graphs](https://ojs.aaai.org/index.php/ICAPS/article/view/13568)는 장애물 주변의 희소 연결을 설계할 참고다. 해당 논문의 격자 장애물 규칙을 우리 선분 충돌 규칙과 같다고 가정하지 않는다.

### 최소 실험 구성

| 변형 | 목적 |
| --- | --- |
| R1_FULL_BOUNDARY | 모든 경계 정점을 유지한 보수적 압축; 정확성 기준 및 간선 증가 비용 확인 |
| R1_SPARSE | 검증한 비지배 macro edge만 생성; 주 성능 후보 |
| R1_ADAPTIVE | 압축 그래프 규모와 추정 이웃 수만으로 압축/원래 그래프를 선택; 조건부 확장 |

최종 평가에는 검증 데이터에서 선택한 한 변형만 올린다. 작은 지도의 전처리 손해가 크면 단일 질의용으로 탈락시킬 수 있으며, 반복 질의에서만 이기면 그 조건으로 적용 범위를 제한한다. 압축이 유리한 개방형 지도뿐 아니라 좁은 복도와 높은 벽 밀도에서의 퇴행도 측정한다.

추가 기록: 원래 정점 수, 남은 정점 수, 영역 수, 생성·검사한 macro edge 수, 경계 fan 스캔 수, 분할 시간, 쿼리 삽입 시간, 복원 시간. 경계 정점을 줄여 확장 수만 좋아 보이지만 큰 fan을 스캔하는 구현은 전체 시간에서 걸러낸다.

## 5 R2 필요한 장애물의 단계적 반영 실험

### 알고리즘과 종료 조건

전체 벽 집합을 B, 현재 활성 벽을 S라고 한다. 외곽 경계는 항상 반영한다. S만 반영한 완화 문제를 **정확하게** 풀고, 반환 경로를 B 전체에 대해 검사한다. 충돌하면 그 경로와 충돌한 새로운 벽을 S에 추가한다. 유효하면 종료한다.

S가 B의 부분집합이면 완화 최적 길이는 실제 최적 길이의 하한이다. 완화 최적 경로가 B에서도 유효하면 실제 최적값과 같으므로 정확한 종료 증명으로 사용할 수 있다. 실패 회차마다 적어도 하나의 새 벽을 추가하면 벽 m개에서 최대 m+1번의 정확 탐색으로 끝난다. 완화 문제 자체가 불가능하면 원래 문제도 불가능하다.

실용 구현은 **실패한 완화 탐색 3회 뒤 모든 벽을 활성화해 정확 탐색으로 전환**한다. 따라서 기본 재탐색 상한은 4회다. 이 fallback의 시간과 앞선 실패 회차를 모두 합산한다. 충돌한 적 없는 벽도 미리 넣을 수 있지만, 존재하지 않는 벽 ID나 임의의 추가 장애물을 AI가 만들도록 허용하지 않는다.

기존 완화 그래프와 더 강한 제약의 그래프 사이에서 오래된 간선·거리 캐시를 무조건 재사용하지 않는다. 벽 활성화로 간선이 사라지면 관련 캐시와 탐색 상태를 갱신한다. 전체 B의 고비용 그래프를 몰래 선계산해 R2의 비용에서 제외하지 않는다.

이는 [Basel의 CEGAR](https://ojs.aaai.org/index.php/ICAPS/article/view/13605)와 [CMU의 LazySP](https://www.ri.cmu.edu/pub_files/2016/3/paper-lazysp.pdf)를 우리 벽 단위 제약에 적용하는 설계다. [Generalized Lazy Search](https://arxiv.org/abs/1904.02795)가 지적하듯 충돌 검사를 줄이는 것과 재탐색 비용을 줄이는 것은 별도 문제이므로 두 비용의 합을 평가한다.

### 최대 여섯 변형의 단계적 비교

| 변형 | 초기 활성 벽과 갱신 방식 | 분리할 효과 |
| --- | --- | --- |
| R2_EMPTY_FIRST | 내부 벽 없이 시작, 첫 충돌 벽 하나씩 추가 | 가장 단순한 지연 반영 |
| R2_EMPTY_BATCH | 내부 벽 없이 시작, 현재 경로가 만난 벽을 한 번에 추가 | 반복 횟수 감소 |
| R2_RULE_BATCH | 시작과 목표의 직선을 막는 벽부터 반영, 일괄 추가 | 저렴한 기하 규칙 |
| R2_RANDOM_MATCHED | RULE 또는 학습 선택기와 같은 수의 벽을 무작위 선택 | 초기 벽 수 자체의 효과 |
| R2_PROGRAM_BATCH | 개발 데이터로 고른 결정론적 점수식으로 벽을 선택, 일괄 추가 | 오프라인 AI 설계의 추가 효과 |
| R2_INCREMENTAL | 검증 전 개발 단계에서 가장 유망한 규칙에 정확한 상태 갱신 추가 | 재시작 대비 상태 재사용 |

한 번에 6개를 모두 만들지 않는다. 앞의 세 가지를 먼저 측정하고, 재탐색 비용이 병목일 때만 incremental을 구현한다. R1이 통과하면 선택된 R2에 R1을 붙여 `A_OCT / R1 / R2 / R1+R2`의 2×2 비교를 수행한다. R2 단독이 실패해도 R1 결합이 재탐색 비용을 바꿀 수 있으므로 결합 파일럿 한 번은 허용한다.

### AI를 사용한다면 무엇을 학습할지

온라인 경로마다 LLM을 호출하기 전에, LLM이 **벽 우선순위 점수식**을 최대 60회 제안하도록 한다. 입력 특징은 직선 교차 여부, 벽 길이, 끝점까지의 상대 거리, 경계 연결 여부 등이다. 생성물은 허용된 특징·산술·비교 연산만 갖는 작은 표현식으로 제한한다. 개발 데이터에서만 후보를 평가하고 최대 3개를 검증한 뒤 하나를 고정한다. 실제 탐색 중에는 이 식만 실행한다.

정확한 최단 경로·전체 거리장·평가 결과를 입력 특징에 넣지 않는다. RULE 및 같은 벽 수의 RANDOM을 이기지 못하면 AI 선택기를 제거한다. 연구 기여는 CEGAR 자체의 발명이 아니라, 이 문제에서 제약 선택과 정확한 공간 압축의 결합이 주는 검증된 추가 이득이어야 한다.

추가 기록: 활성 벽 수의 변화, 완화 탐색별 확장·시간, 새 충돌 벽 수, 전체 검증 간선 수, 캐시 갱신량, fallback 비율, 최종 길이 하한과 반환 길이.

## 6 R3 위상 기반 안내 실험

### AI의 역할과 길이 상한

지도에서 연결된 벽과 통과 구역을 구성하고, 장애물을 서로 다른 방향으로 우회하는 후보 구조를 최대 3개 생성한다. 같은 출입구 순서를 갖는 후보는 중복 제거한다. LLM에는 벽·출입구 ID와 기하 특징을 주고 **후보 ID의 순위만** 반환하게 한다. 좌표 생성이나 경유점 강제 통과는 하지 않는다.

초기 구현은 출입구 순서에 대한 구조적 서명을 사용한다. 엄밀한 homotopy 분류를 주장하려면 연결 장애물·경계와 cut의 조건 및 축약 word 처리를 따로 검증한다. 그 전에는 명칭을 ‘위상 정보를 활용한 안내’로 한정한다. [Path Homotopy Invariants](https://arxiv.org/abs/1710.02871)는 서명을 만드는 수학적 참고이며, 무한히 많은 경로 분류를 탐색 상태로 펼치지 않는다.

후보 생성은 작은 출입구 그래프에서 서로 다른 구조를 제한적으로 나열하는 방식으로 시작한다. 원래 격자 전체의 최단 경로를 먼저 구해 후보에 넣지 않는다. 후보 생성에 탐색을 썼다면 그 비용을 모두 준비 비용으로 기록한다. 후보끼리 순위를 매기는 기하 규칙이 이미 충분하면 LLM 분기를 중단한다.

anchor는 admissible octile을 유지한다. `g+h <= w × min_OPEN(g+h)`인 노드만 FOCAL에 넣고, 현재 부모 경로의 출입구 순서와 후보의 일치 여부·후보 순위·다음 출입구까지의 거리를 보조 순위로 사용한다. g가 개선되면 부모 경로 서명과 큐 항목도 갱신한다. 예측에 맞지 않는 노드도 OPEN에서 제거하지 않는다.

완전한 OPEN 관리, 재개방, FOCAL 자격 확인, 목표 선택 시 종료 조건을 지키면 `L <= w L*`를 유지하는 구조다. **w=1, 1.01, 1.02**를 비교하고 주 설정은 1.02로 사전에 지정한다. w=1의 효과는 최적성을 보존하는 동점 처리 등의 이득으로 제한될 수 있다. [TransPath](https://ojs.aaai.org/index.php/AAAI/article/view/26465)가 이미 학습 안내와 FOCAL을 결합하므로, 그 결합만을 차별성으로 주장하지 않는다.

### 반드시 같은 후보를 공유하는 비교

| 순위 방법 | 설정 |
| --- | --- |
| TOPO_RULE | 후보 생성 시 얻은 저렴한 길이 추정과 출입구 수로 순위화 |
| TOPO_RANDOM | 동일 후보의 순서만 무작위 변경; 고정된 3개 시드 |
| TOPO_LLM | 동일 후보를 고정된 한 모델이 순위화 |

공통 FOCAL과 이 세 방법을 같은 문제·같은 후보·같은 w에서 비교한다. 후보가 2개 미만인 문제는 안내를 생략하고 기본 FOCAL로 푼다. 이런 문제도 전체 적용 정책의 성능 분모에 포함한다. ‘안내 가능 문제만’의 결과는 보조 분석으로 따로 제시한다.

개발에서 후보 수 2와 3을 비교해 하나를 고정한다. 기본 모델은 기존 프로젝트에서 사용한 `meta-llama/Meta-Llama-3-8B-Instruct`, BF16, greedy, batch 1로 계획하며 실행 시 revision·가중치·토크나이저 해시를 기록한다. 파싱 실패·중복 ID·모르는 ID·출력 중단은 재생성하지 않고 RULE로 전환하며 실패율에 포함한다. 평가 결과를 보고 프롬프트를 고치지 않는다.

새 좌표 프롬프트와의 직접 비교는 별도 출력 수집이 필요하므로 주 실험에 넣지 않는다. 기존 좌표 결과는 개발 단계의 참고 비교로만 사용한다. 주 실험은 우선 ‘같은 구조적 후보에서 LLM 순위가 규칙을 능가하는가’를 답한다.

## 7 데이터 분리와 생성 조건

### 지도 단위 분리

| 데이터 | 규모 | 용도 |
| --- | --- | --- |
| 기존 관측 데이터 | 원본 100지도 1,000문제 및 이미 본 확대·미로 데이터 | 오류 재현·개발·기존 결과 연결; 새 미관측 검증으로 재사용하지 않음 |
| 신규 개발 | 4유형 × 15지도 × 10문제 = 600문제 | 구현·제한된 설정 탐색·점수식 생성 |
| 신규 검증 | 4유형 × 15지도 × 10문제 = 600문제 | 최종 변형 선택·진행 여부 판단 |
| 신규 최종 평가 | 4유형 × 50지도 × 10문제 = 2,000문제 | 고정 설정의 최종 비교 |
| R3 최종 부분집합 | 최종 평가에서 유형당 20지도 × 지도당 5문제 = 400문제 | LLM 포함 조건 비교; 모델 성능을 주장할 실제 평가 범위 |

R3 부분집합은 지도 해시 순서와 문제 인덱스로 고정하며, 쉬움·어려움·모델 성공 여부로 고르지 않는다. 2,000문제 전체의 비 AI 결과와 400문제의 AI 결과를 분모를 섞어 비교하지 않는다. 지도당 10문제는 독립 지도 10개가 아니다.

### 네 가지 지도 유형

| 유형 | 생성 조건 | 확인할 실패 양상 |
| --- | --- | --- |
| A 원본 유사 선분 지도 | 51×31, 가로·세로 벽 각각 1~4개; 원본의 좌표 샘플링 규칙을 참고 | 작은 지도에서 준비 비용이 이득을 상쇄하는가 |
| B 높은 벽 밀도 | 101×61, 총 벽 수 12 / 24를 균형 배정; 교차·접촉 허용 | 압축 경계 증가 및 R2 재탐색 증가 |
| C 복도와 막다른 길 | 101×61, 교대 벽·분기·막다른 길, 통로 폭 1 / 2 / 3을 균형 배정 | 잘못된 우회 순위, 경계와 연결된 벽, 좁은 통로 |
| D 여러 우회 선택 | 101×61, 분리 장애물과 연결 벽 묶음, 비대칭 출입구 | 구조적 후보의 다양성과 LLM 순위의 유용성 |

원본 생성 코드에는 사람이 Good/Bad를 고르는 단계가 있다. 새 A 유형에서는 사람의 선별을 제거하므로 ‘원본과 동일 분포’라고 부르지 않는다. A 유형의 주 질의는 원본처럼 직선이 막히는 조건으로 샘플링하되, 나머지 유형은 같은 연결 성분의 시작·목표를 샘플링한다. 직접 연결 가능한 비율도 보고한다. 모든 유형의 최단 거리와 우회 비율은 사후 설명 변수이며 좋은 결과만 남기는 필터가 아니다.

최종 지도는 구현과 설정 고정 후 별도 시드로 생성한다. 생성 실패·질의 재샘플링 사유와 횟수를 기록하고, 알고리즘 성능을 보고 지도를 교체하지 않는다. 독립 정답 탐색기로 도달 가능성을 분류한다. 최적 길이 비율을 평가하는 주 표는 도달 가능한 문제로 구성하고, 불가능 문제는 아래 별도 검증에 보존한다. 회전·반사·배율 변형은 같은 원형 지도 그룹에 묶는다.

## 8 추가 조건은 세 축으로 제한

**좌표 확대:** 최종 지도 유형별 10개, 총 40개에서 첫 두 문제를 선택해 배율 1 / 2 / 4 / 8을 비교한다. 총 320조건이며 1배 80문제는 주 평가와 중복, 추가 문제는 240개다. 벽 수는 고정된다. 확대를 새 독립 지도 320개로 세지 않는다. 모든 좌표와 경계 해석을 함께 변환한다.

**지도 재사용:** 유형별 5개, 총 20개 지도에서 Q=1 / 5 / 10의 누적 질의를 비교한다. 첫 workload는 기존 10개 시작·목표로 목표가 바뀌고, 두 번째는 목표 하나에 서로 다른 시작 10개를 둔다. 두 번째의 추가 문제는 200개다. 같은 질의를 단순 반복하는 캐시 적중 실험으로 대체하지 않는다. 각 방법에 합법적인 지도 캐시를 허용하되 정답은 공유하지 않는다.

**반례 및 경계 검증:** 별도 20지도 × 5개의 도달 불가능 질의 100개, 작은 무작위 격자 2,000질의, 시작=목표·벽 끝점·대각선 교차·경계 접촉·길이 0인 벽·분리 영역·연결 벽 묶음을 포함한다. 최종 성능 평균과 섞지 않고 정확성 결과를 모두 공개한다.

FMM 재사용 비교에서는 기본 속도의 FMM을 같은 목표에서만 재사용한다. 목표가 바뀌면 다시 계산한다. LLM 제안에 따라 속도장이 달라지는 FMM은 동일 목표라는 이유만으로 재사용하지 않는다. **같은 목표 workload에는 역방향 Dijkstra 거리장과 경로 복원도 대조군으로 추가**한다. 이미 목표별 전처리를 허용하면서 정확한 거리장이라는 강한 대안을 빼면 FMM의 이득을 과대평가할 수 있다.

## 9 계측과 공정한 비용 계산

| 범주 | 필수 기록 |
| --- | --- |
| 결과 | 도달 여부, 경로 유효성, 길이 L, 독립 정답 L*, L/L*, 최단 길이 일치, 상한 위반 |
| 탐색 | 확장 수, 재개방 수, 모든 heap push/pop, stale pop, 이웃 후보 수, relax 시도 및 성공, peak OPEN |
| 기하 | 단위 이동 충돌 검사, 벽과의 기본 교차 검사, cache hit/miss, macro edge·fan 검사, 최종 경로 검증 |
| 후보별 추가 비용 | 전처리·안내 생성·점수식 평가·재탐색·상태 갱신·복원, R2 회차별 계측 |
| 시간 및 메모리 | 지도 준비, 목표별 준비, 질의별 준비, 추론, 탐색, 필수 검증, 복원, 전체 시간, peak RSS |
| 모델 | 모델 해시, 입력/출력 토큰, 생성 시간, 파싱 실패, fallback, 오프라인 생성과 평가 비용 |

**원래 heap pop, 새 탐색의 확장 수, FOCAL의 anchor heap pop은 다른 지표다.** 이를 하나의 ‘연산량 감소율’로 합치지 않는다. 주 계산 성능은 확장 수와 전체 시간을 함께 보고, 기하·간선·큐 연산으로 원인을 설명한다. macro edge 확장 한 번을 원래 단위 정점 확장 한 번과 같은 작업량이라고 해석하지 않는다.

단일 질의의 전체 시간은 지도 준비부터 반환 경로 복원과 알고리즘이 요구하는 검증까지다. R2의 실패 회차와 fallback도 포함한다. 연구용 독립 Dijkstra 정답 생성과 결과 감사는 별도 실행비로 기록하고 온라인 시간에서 제외한다. 모든 방법의 공통 감사 검사와 알고리즘 내부의 필수 검증을 구별한다.

반복 질의 평균은 `(지도 전처리 + 목표별 준비의 합 + 질의별 전체 비용의 합) / Q`로 계산한다. 지도·목표·질의에 종속되는 준비를 구별해 Q로 잘못 나누지 않는다. 손익분기 질의 수는 측정값으로 산출하며 질의당 절약이 없으면 ‘손익분기 없음’으로 보고한다.

주 시간 측정은 같은 호스트에서 CPU 한 프로세스, 동일 스레드 설정으로 수행한다. 방법 순서를 블록마다 섞어 5회 측정하고 문제별 중앙값을 쓴다. 정량 계측이 시간에 영향을 줄 수 있으므로 상세 카운터 수집과 시간 측정은 같은 고정 코드의 별도 모드로 하며 경로·길이 일치를 확인한다. 시스템 준비용 warmup은 별도 기록하고, 단일 질의 측정에서는 각 회차의 지도·목표 캐시를 비운다.

프로세스/모델은 준비된 상태의 온라인 시간과 최초 모델 로딩 시간을 구분한다. 새로 수집한 모델 응답의 첫 생성 시간을 저장하고 로컬 탐색만 반복 측정한다. 5회 시간 측정을 위해 LLM을 5번 재호출하지 않는다. 캐시 재생 시간으로 온라인 추론 시간 우위를 주장하지 않는다.

기본 실패 상한은 방법·질의당 60초, peak RSS 8 GiB로 계획한다. 확대 지도만 다른 상한이 필요하면 개발 파일럿에서 정하고 최종 고정 전에 기록한다. timeout·OOM·오류를 제거한 성공 문제끼리의 빠른 평균으로 승리를 선언하지 않는다.

| --- | --- | --- |
| 공통 기반 | 독립 Dijkstra와 일치, 기존 충돌 판정 차등 검증, 상한 테스트 통과 | 기하 규칙 불일치·경로 복원 오류가 남으면 성능 평가 보류 |
| R1 | 신규 검증에서 정확성 유지, 준비 포함 시간 비율 ≤0.90, 확장 수 비율 ≤0.80을 목표 | 단일 질의 실패 시 반복 질의 전용 가능성만 평가 |
| R2 | 동일 정확 탐색 대비 누적 시간 ≤0.90을 목표, 모든 회차 합산 | 벽 검사는 줄어도 재탐색으로 느리면 탈락; R1 결합 파일럿 한 번 허용 |
| R3 | w=1.02에서 LLM이 RULE보다 로컬 확장 수 ≥10% 감소를 목표 | 규칙과 차이가 작으면 모델 추가 실행 중단 |

공통으로 유효 경로 누락·정확성 또는 길이 상한 위반은 0건이어야 한다. 검증의 P95 문제별 시간 비율이 1.5를 넘으면 전체 평균이 좋아도 해당 조건의 퇴행을 분석하고 적용 범위를 제한한다. 최종 평가에서는 새로운 제한 규칙을 만들지 않는다.

### 최종 결과의 판정

1. **정확 탐색 개선:** R1/R2/R1+R2는 최단 길이 일치 100%가 필수다. A_OCT 대비 전체 시간의 기하평균 비율 ≤0.90, 확장 수 비율 ≤0.80을 실용 목표로 두며, 시간 개선의 동시 신뢰구간 상한이 1 미만이어야 강한 개선 결론을 낸다.
2. **R2의 추가 가치:** R1+R2가 R1보다 전체 시간을 더 줄이는지 별도로 판단한다. A_OCT만 이기고 R1보다 느리면 R2의 추가 기여를 주장하지 않는다.
3. **N보다 나은 결과:** N_CLEAN 대비 경로 품질이 나빠지지 않으면서 확장 수와 전체 시간도 감소하는지가 별도 도전 목표다. 정확 탐색 기준을 통과해도 이 조건을 못 넘으면 ‘빠른 정확 탐색 개선’으로만 결론 낸다.
4. **온라인 LLM의 가치:** TOPO_LLM은 같은 w의 RULE 및 RANDOM보다 좋아야 하고, 추론을 포함한 전체 시간도 개선되어야 온라인 채택한다. 탐색만 좋아지면 안내 정보의 효과와 배포 효용을 구분한다.
5. **가족별 조건:** 한 유형에서만 이기면 그 조건의 개선으로 명시한다. 검증에서 정한 적용 규칙을 최종 평가에 그대로 적용하고, 실패하는 유형을 사후에 삭제하지 않는다.

근사 탐색은 평균 초과율뿐 아니라 P95·최대 초과율과 각 문제의 `L <= wL*`를 검사한다. w=1.02는 모든 문제에서 N보다 짧다는 뜻이 아니므로 실제 대응 비교를 별도로 한다. Conformal 보정이나 모델 신뢰도는 이 길이 상한을 대신하지 않는다.

## 11 통계와 최종 데이터 보호

시간·확장 수의 문제별 비율에 로그를 취하고 지도 내 평균 후 지도 간 평균을 계산해 기하평균 비율로 보고한다. 유형별 지도 수가 같으므로 주 종합 값에서는 네 유형이 같은 비중이다. 산술평균 초과 길이, 최단 길이 일치율, P95 및 실패율도 함께 제시한다.

bootstrap은 유형별로 **지도 그룹을 재표집**하고 같은 지도의 모든 질의·배율·방법을 함께 가져온다. 10,000회, 고정 시드를 사용한다. R3의 3개 무작위 순위 시드는 지도 수로 세지 않고 한 문제 안의 알고리즘 변동으로 먼저 집계한다.

확증 비교는 최대 네 개로 제한한다: `R1/A_OCT`, `R2/A_OCT`, `R1+R2/R1`, `TOPO_LLM/TOPO_RULE(w=1.02)`. 개발·검증에서 탈락한 항목은 생략하되 전체 네 비교의 보수적 기준을 유지한다. 각각의 시간 비율에는 Bonferroni 기준 양측 98.75% bootstrap 구간을 사용해 네 비교의 다중성을 반영한다. 일반 95% 구간과 나머지 비교는 탐색적으로 표시한다. 이 bootstrap 절차의 작은 표본 성질을 엄밀한 유한 표본 보장으로 표현하지 않는다.

600개 검증 문제는 진행 판단과 최종 변형 선택에 한 번 사용한다. 검증을 본 뒤 대규모 설정 변경이 필요하면 그 분할은 개발용으로 전환하고 새 검증 지도를 만든다. 최종 2,000문제는 소스·설정·모델·데이터 생성기·통계 코드를 고정한 뒤 한 차례 평가한다. 버그 수정이 필요하면 실행 버전을 올리고 관련 비교군을 함께 다시 실행하며 이전 결과를 보존한다.

사전 지정한 200개 평가 지도는 시작 규모이며 검정력 보장을 뜻하지 않는다. 검증 지도의 로그 비율 분산으로 10% 시간 개선에 대한 검정력 시뮬레이션을 수행한다. 80%에 못 미치면 최종 데이터를 열기 전에 총 평가 지도를 400개까지 늘릴지 결정하고 프로토콜을 새로 고정한다. 결과를 본 뒤 유의해질 때까지 지도를 추가하지 않는다.

## 12 계산 예산과 실행 순서

| 순서 | 작업 | 완료 산출물 |
| --- | --- | --- |
| 0 | 새 공통 기준·독립 정답·충돌 및 큐 관리 검증 | 정확성 검증 기록, 동일 호스트 기준 수치 |
| 1 | R1 보수 구현 → 희소화, 개발·검증 | 한 개 R1 고정 설정 또는 탈락 사유 |
| 2 | R2 단순 세 변형 → 선택기/상태 재사용 필요성 판단 | 한 개 R2 고정 설정, 회차별 비용 분석 |
| 3 | R1+R2 결합 파일럿과 반복 질의 대조 | 결합 진행 여부, 준비 비용 손익분기 |
| 4 | R3 RULE부터 구현 → 제한된 LLM 비교 | 안내 가능 비율, 동일 후보 순위의 독립 효과 |
| 5 | 통계 코드·최종 설정 고정 → 신규 최종 평가 | 고정 프로토콜, 결과 및 검증 파일 |
| 6 | 정확/근사, 단일/반복, 전체/유형별 판정 | 채택·조건부 채택·탈락 표와 최종 보고서 |

최소 완료 단위는 단계 0~3이다. R3는 앞선 결과와 무관하게 연구 질문상 필요할 때 진행하되, 규칙 대비 모델 효과가 약하면 확대하지 않는다. 구현 일정은 정확성 검증의 난도에 영향을 받으므로 고정 일수보다 위 산출물의 통과 여부로 관리한다.

**CPU 계획:** 주 평가 8개 비교군과 최대 3개 정확 후보는 2,000문제에서 최대 22,000개 논리적 결과를 만든다. 시간 5회 반복은 별도 측정이며 독립 문제 수를 늘리지 않는다. 확대·재사용 및 정확성 검증은 별도 예산으로 기록한다.

**모델 계획:** 기본은 기존 로컬 Llama 모델을 사용하고 새 유료 API 호출은 0건이다. R2 점수식 생성 최대 60회, R3 개발 120회·검증 120회·최종 400회로 합계 최대 700회 생성한다. 후보가 부족하거나 앞 단계에서 탈락하면 줄어든다. R3 순위 응답은 최대 256 새 토큰, R2 점수식은 최대 512 새 토큰을 사용한다. 입력과 출력이 실제 모델 문맥 한도에 맞는지 실행 전에 검증한다. 모델 접근이 안 되면 다른 모델로 조용히 바꾸지 않고 AI 분기를 미실행으로 남긴다.

R3 최종 평가는 같은 최대 400개 응답을 w 세 값에서 재사용한다. RULE 1개, RANDOM 3개 시드, LLM 1개 × w 3개 × 400문제로 최대 6,000개 논리적 결과이며, 비교군은 같은 400문제의 결과를 사용한다. 추론 비용은 각 w를 독립적으로 배포할 때 한 번씩 필요한 비용으로 계산하되, 실제 수집 비용은 공유된 한 번만 기록한다.

모델을 추가 비교하거나 새 좌표 응답을 수집하는 것은 이번 기본 예산에 포함하지 않는다. 최종 지도를 400개로 늘리면 CPU 예산만 별도 갱신하고, R3 부분집합 규모는 별도 변경을 명시하지 않는 한 80지도 400문제로 유지한다.

최종 실행 산출물은 `protocol_frozen.json`, `data_manifest.json`, `environment.json`, `per_case.jsonl`, `timings.jsonl`, `verification.json`, `report.md`로 구성한다. 소스·데이터·모델 해시, 실패와 중단 이력, 상태, 실제 모델 호출 수를 포함한다. 단계별로 결과를 저장해 재개할 때 완료된 응답을 더 좋은 답으로 바꾸지 않는다.

최종 보고서의 첫 표에는 후보별로 **최단 길이 또는 상한 준수, 전체 시간, 확장 수, N 대비 관계, 적용 가능한 조건, 채택 여부**를 함께 넣는다. 그 뒤 비용 분해와 대표 실패 사례를 제시한다. 가장 좋은 지도 한두 개의 그림으로 전체 성능을 대신하지 않는다.
