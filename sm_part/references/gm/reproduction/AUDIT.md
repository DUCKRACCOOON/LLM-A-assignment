# 구현 출처와 검증 기록

## 출처

`core.py`의 A*/LLM-A*는 공식 MIT 코드의 탐색·휴리스틱·queue·필터 동작을 이식했다. 원본 작성자의 기여를 우리의 새 알고리즘으로 주장하지 않는다. `source_code`는 원 커밋을 보존한다. `api.py`, 실험 실행·집계·진단, 입력 어댑터, V-Gate의 검증·fallback은 이 작업에서 추가했다.

## 논문 / 원 코드 / 이번 선택

| 항목 | 근거와 채택한 동작 |
| --- | --- |
| 최종 목표 | start/goal은 고정. waypoint는 휴리스틱 target이며 필수 경유점이 아님 |
| LLM-A* 우선순위 | g + 유클리드 거리(goal) + 유클리드 거리(target) |
| target 갱신 | 원 코드처럼 이웃 좌표와 일치하면 충돌·CLOSED 검사보다 먼저 갱신 |
| OPEN | target 전환 때 중복 엔트리까지 재삽입, 같은 f는 좌표 사전순 |
| CLOSED | 중복 pop도 확장·operation에 포함. membership만 set으로 가속 |
| storage | g의 항목 수. 충돌 이웃의 inf도 포함 |
| waypoint filter | 경계에서 한 칸 떨어진 유효 점도 탈락할 수 있는 원 필터 유지 |
| 장애물 | 충돌 선분은 양 끝 포함, obs 필터는 range 끝 미포함. 길이 0 선분은 원 Shapely와 같이 무시 |
| 응답 없음 | missing list는 start/goal fallback으로 g+2h. 평가할 수 없는 list는 실패 기록. 3개 이상 숫자는 원본처럼 앞 두 개 사용 |
| 입력 | deepcopy에 해당하는 독립 내부 상태; 원본의 range 상한 변경이 다음 실행에 전파되지 않음 |
| DWA | 2에서 시작, non-goal pop마다 0.99배·하한 1·OPEN 재계산. 원 구현이 없으므로 구현 가정 |
| 모델 | 과제 GPT-4o mini + 논문 GPT-3.5 계열; Llama3의 대체를 명시 |
| 호출 | instruct Completion에서 Chat Completions로 변경; 원 프롬프트 문자열 유지; newline stop 제거 |
| LLM-only | 원 응답 polyline. search로 수리하지 않으며 탐색 지표는 N/A |
| 집계 | 방법/A*의 기하평균. 실패 포함 전체 valid 비율 + metric별 실제 분모 |

## 검증

`results/verification/offline_checks.json`에 30문제 ×3조건=90건의 원본 경로·operation·storage·length 일치 기록이 있다. Shapely와 3,000개의 연속 선분 충돌 판정을 비교했으며 30개 A* 경로 길이는 독립 Dijkstra와 비교했다. 이 검사는 고정 응답을 사용하는 오프라인 검사로, 실제 LLM 재현 성능과 구분한다.

초기 검사에서 길이 0 장애물의 처리 차이가 발견되었다. 원 데이터 map index 60 등에 `[y,x,x]` 선분이 있고 Shapely는 이를 선분 교차로 처리하지 않는다. 이를 보존하도록 수정한 뒤 전체 검사가 통과했다. 이 사실을 숨겨 유효 데이터만 선택하지 않았다.

API 접근 확인은 두 모델 각각 짧은 1회 호출, 파일럿은 실제 180회 호출이다. 파일럿에서 4개 length 종료와 파싱 실패가 발생했으며 생성 한도와 실패 처리 방식을 유지했다. 파일럿 응답을 전체 재현에 재사용한다.

## 해석상 제한

공식 코드의 동작 보존이 이론적 최적성·완전성의 일반 증명은 아니다. 특히 시간에 따라 바뀌는 휴리스틱과 CLOSED 비재개방은 따로 분석해야 한다. 성공률 100%가 나와도 측정한 데이터에 대한 관측값이다. 유효 polyline의 연속 길이는 grid 경로보다 짧을 수 있어 같은 이동 모델의 최적해라고 부르지 않는다.

LLM API 지연에는 통신·서비스 대기 시간이 포함된다. 로컬 search seconds에는 API 호출이 포함되지 않는다. 캐시 비용을 공유한 실험 재생과 처음부터 생성하는 배포 비용은 다르다. V-Gate도 실제 배포에서는 LLM을 먼저 호출하므로 g+2h보다 API 비용이 절감된다고 주장하지 않는다.

## AI 지원과 사용자의 검토

이 작업에서는 Codex가 구현, 검증 스크립트, 실험 실행과 보고서 초안 작성을 도왔다. 저장된 실제 응답·실행 로그·커밋이 결과의 근거다. 사용자는 제출 전에 수식, 지표, 결과 해석과 수정 내역을 이해하고 문장을 검토해야 한다. 이를 AI 탐지 회피를 위한 문장 변경으로 대체하지 않는다. 개인 기여 보고서는 본 공유 저장소에 작성하지 않는다.

최종 원문 응답 검증에서 GPT-4o mini가 장애물 triple 목록을 마지막 list로 반환한 경우가 발견되었다. 원본은 앞 두 숫자를 waypoint로 처리한다. 처음의 엄격한 parser는 이 32건을 실패로 분류했으므로, 실제 원본 응답 재생으로 차이를 확인한 후 baseline에 한해 원 동작을 복원하고 전 결과를 캐시에서 다시 계산했다. LLM-only/제안안의 strict schema와 구분한다. 초기 집계는 `results/development/strict_parser/`에 미확정 개발 기록으로 보존하며 최종 보고서에 사용하지 않는다.
