# GPT 재현 결과와 논문 결과의 성능 차이 분석

분석일 2026-10-14. 본 실험 1,000문제, 3,000개 GPT 응답, 8,000개 평가 행과 기존 경유점 제거 실험 1,000건을 대조했다. 추가 API 호출과 탐색 재실행 없이 저장된 결과를 재집계했다.

**현재 재현에서 낮은 탐색량을 설명하는 가장 강한 근거는 목표 지향 휴리스틱의 효과다. GPT 경유점을 전부 제거한 `g+2h` 탐색이 세 GPT 결합 조건보다 집계 연산량·저장량·경로 길이에서 모두 좋았다.** 특히 Few-shot의 50.8%는 실제 중간 경유점 없이 이 탐색으로 동작했다. 다만 논문 당시 응답과 경유점 분포가 없으므로, 논문과의 수치 차이 중 각 요인이 차지하는 몫까지 확정할 수는 없다.

## 논문보다 좋아진 지표의 범위

모든 수치는 문제별 A* 대비 비율의 기하평균이다. 낮을수록 좋으며, 경로 길이는 이번 실험에서 유효한 경로만 집계했다. 아래 GPT 결합 조건은 모두 1,000문제에서 유효 경로를 얻었다. 논문 값은 [논문 v2 Table 1](https://arxiv.org/html/2407.02511v2#S4.T1), 재현 값은 [기존 결과](summary.json)에서 확인했다.

| 조건 | 연산량 논문 → 재현 | 저장량 논문 → 재현 | 경로 길이 논문 → 재현 |
| --- | ---: | ---: | ---: |
| GPT + LLM-A* Few-shot | 57.39% → 40.29% | 74.96% → 61.20% | 102.44% → 102.17% |
| GPT + LLM-A* CoT | 69.50% → 56.62% | 83.65% → 74.64% | 102.54% → 102.77% |
| GPT + LLM-A* RePE | 85.47% → 74.10% | 96.53% → 87.78% | 102.41% → 102.53% |

연산량과 저장량은 세 조건 모두 개선됐지만, CoT와 RePE의 경로는 논문보다 조금 길다. Few-shot의 연산량 비율은 17.10%p 낮아졌고, 보고된 비율끼리 비교한 상대 감소는 약 29.79%다. 이를 실제 실행시간이 29.79% 빨라졌다는 뜻으로 해석할 수는 없다.

## 중간 경유점이 없으면 목표 방향의 가중 탐색이 된다

[재현 코드](../../reproduction/core.py)의 탐색 우선순위는 다음과 같다. `h(n)`은 목표까지의 유클리드 거리이며, `t`는 현재 경유점이다.

```text
A*:       f(n) = g(n) + h(n)
LLM-A*:   f(n) = g(n) + h(n) + distance(n, t)
경유점이 없을 때 t = goal
          f(n) = g(n) + 2h(n)
```

경유점 목록이 비었거나 필터링 후 모두 사라지면 시작·목표를 보충하므로, 다음 안내점이 곧 목표가 된다. 이 동작은 [공개 저자 코드](../../source_code/llmastar/pather/llm_a_star/llm_a_star.py)의 구조도 따른다. 경유점이 없을 때 일반 A*로 돌아가는 구조가 아니다.

`g+2h`는 목표까지의 거리를 더 강하게 반영해 탐색량을 줄일 수 있지만 최단 경로 보장은 약해진다. 이번 데이터에서는 A*보다 경로가 약 2% 길어지는 대신 탐색량이 크게 줄었다. [기존 경유점 제거 실험](no_waypoint_ablation.json)을 동일한 1,000문제로 재집계한 결과는 다음과 같다.

| 조건 | 연산량 | 저장량 | 경로 길이 | 유효 경로 |
| --- | ---: | ---: | ---: | ---: |
| 중간 경유점 없음 `g+2h` | 34.32% | 56.23% | 102.02% | 100% |
| GPT + LLM-A* Few-shot | 40.29% | 61.20% | 102.17% | 100% |
| GPT + LLM-A* CoT | 56.62% | 74.64% | 102.77% | 100% |
| GPT + LLM-A* RePE | 74.10% | 87.78% | 102.53% | 100% |

같은 문제에서 GPT 경유점을 사용한 경우와 제거한 경우를 짝지으면, 경유점 사용 시 연산량은 Few-shot 17.42%, CoT 65.01%, RePE 115.94% 더 많다. 이는 문제 난이도가 다른 집단의 단순 비교가 아니라 같은 문제끼리 나눈 비율의 기하평균이다.

| 프롬프트 | 경유점 사용 시 연산량 감소 | 동일 | 증가 | 경유점 없는 조건 대비 연산량 비율의 95% 구간 |
| --- | ---: | ---: | ---: | ---: |
| Few-shot | 130문제 | 601문제 | 269문제 | 112.88~122.44% |
| CoT | 218문제 | 179문제 | 603문제 | 154.37~177.42% |
| RePE | 173문제 | 90문제 | 737문제 | 197.28~236.52% |

구간은 같은 지도 안의 10문제를 묶어서 100개 지도를 2,000회 재표집한 paired cluster bootstrap으로 계산했다. 저장된 GPT 응답을 고정한 데이터 표본의 불확실성만 다루며, 모델을 다시 호출했을 때의 변동이나 논문 대비 차이의 신뢰구간은 아니다. 일부 문제에서는 경유점이 도움이 되므로 모든 문제에서 불필요하다고 일반화할 수 없다.

## Few-shot의 절반은 중간 경유점을 사용하지 않았다

원문 응답 3,000개를 다시 파싱하고 필터링해 저장된 경유점 목록과 대조했다. 시작·목표만 남은 문제들의 연산량·저장량·경로 길이는 기존 경유점 제거 결과와 모두 일치했다.

| 프롬프트 | 중간 경유점 없는 문제 | 파싱 실패 | 시작·목표만 생성 | 중간 점이 필터에서 모두 제거 |
| --- | ---: | ---: | ---: | ---: |
| Few-shot | 508 | 187 | 241 | 80 |
| CoT | 95 | 1 | 2 | 92 |
| RePE | 39 | 6 | 8 | 25 |

Few-shot은 1,000문제 중 508개에서 GPT의 중간 안내점 없이 `g+2h` 탐색을 실행했다. 이 508개 집단의 A* 대비 연산량은 38.03%였다. 경유점이 남은 492개 집단은 42.77%였지만 두 집단의 난이도가 다를 수 있으므로 이 차이만으로 인과관계를 주장하지 않는다. 더 직접적인 비교는 **경유점이 남은 동일한 492개 문제에서 경유점을 제거하는 경우**다. 이때 기존 경유점 사용 조건의 연산량이 제거 조건보다 38.61% 더 많았다.

실제 사례인 [m001-p02 Few-shot 응답](../main/raw/m001-p02-standard.json)은 `[[5,25],[15,15],[45,5]]`다. 중간 점 `[15,15]`가 제거되어 시작·목표만 남았다. 이 문제는 A* 1,296회 대비 결합 탐색 458회로 연산량이 줄었지만, 458회는 경유점 없는 탐색과 정확히 같다. 이 감소를 GPT의 중간 경유점 안내 효과로 볼 수는 없다.

필터링 후 평균 중간 경유점 수는 Few-shot 0.576개, CoT 1.784개, RePE 2.421개였다. 경유점이 많을수록 항상 좋은 것은 아니다. 부정확한 점은 탐색 방향을 비틀 수 있고, 안내점 변경은 탐색 순서와 OPEN 우선순위 재계산을 유발한다. 이번 결과는 경유점 수가 많은 조건에서 연산량도 증가하는 양상이지만, 프롬프트별 경유점 품질 차이도 있으므로 개수 자체의 독립적인 효과는 아직 분리되지 않았다.

## 모델과 생성 설정의 차이는 논문과의 격차를 설명하는 가설이다

[논문 실험 설정](https://arxiv.org/html/2407.02511v2#S4.SS2)은 GPT-3.5-TURBO를 명시한다. [공개 코드의 실제 waypoint 요청](../../source_code/llmastar/model/chatgpt.py)은 `gpt-3.5-turbo-instruct`를 Completion 방식으로 호출하며 `stop=["\n"]`을 기본 적용한다. 이번 [실행 기록](../main/manifest.json)은 `gpt-3.5-turbo-0125`, Chat Completions, 단일 user 메시지, temperature 0, max_tokens 1000, 줄바꿈 stop 제거 조건이다.

이 차이는 답변의 길이, 경로를 못 찾았다는 응답, 경유점 수와 위치를 바꿀 수 있다. 출력 분포가 달라지면 같은 탐색 코드에서도 최종 결과가 달라진다. 특히 이번 Few-shot처럼 경유점이 없어도 강한 목표 지향 탐색을 수행하는 구현에서는, GPT가 경유점을 적게 생성하는 현상이 낮은 연산량으로 연결될 수 있다.

그러나 논문 당시 사용한 정확한 스냅샷, 실행 코드와 원문 응답은 확인되지 않았다. 따라서 “이번 GPT가 더 똑똑해져서 좋아졌다”, “논문에서 경유점을 더 많이 생성했다”, “stop 제거가 개선 원인이다”라고 단정할 근거는 없다.

줄바꿈 stop의 영향은 [예비 비교](../pilot/newline_audit/dev-00-cot.json)에서 관찰된다. 같은 개발 문제에서 stop이 있으면 CoT는 설명 첫 줄만, RePE는 첫 반복 제목만 출력해 최종 경로 목록이 없었다. stop을 제거한 대응 응답에는 경로 목록이 있다. 다만 비교가 개발 문제 1개에 한정되고, 경로 출력이 복구돼도 좋은 경유점이라는 보장은 없다. 본 실험 개선량 전체로 외삽할 수 없다.

GPT 단독 유효 경로 비율도 일관된 능력 향상을 지지하지 않는다. Few-shot은 논문 12.8%에서 6.9%, CoT는 15.2%에서 11.0%로 낮아졌고 RePE만 7.8%에서 11.4%로 높아졌다. 결합 탐색의 낮은 연산량과 GPT 단독의 공간 추론 능력은 별개의 관측이다.

## 평가 방식과 데이터가 미치는 영향

**연산량은 실행시간이 아니다.** 구현의 operation은 중복을 포함한 heap pop 횟수이고 storage는 `g` 딕셔너리 항목 수다. GPT 호출 지연, 토큰 비용, OPEN 재계산 비용을 모두 포함한 실행시간·RAM 사용량이 아니다. 캐시도 탐색 시간에 영향을 주므로 저장된 seconds를 그대로 비교해 속도 개선을 주장하면 안 된다.

**기하평균과 총작업량은 다르다.** Few-shot의 문제별 연산량 비율 기하평균은 40.29%이지만, 1,000문제의 연산 횟수를 각각 합산한 뒤 나눈 값은 61.19%다. CoT는 56.62%와 74.68%, RePE는 74.10%와 91.05%다. 이는 집계 방식의 성질이며 계산 오류가 아니다. 논문도 기하평균을 사용하므로 그 자체가 논문과의 차이를 설명하지는 않지만, “전체 계산량이 약 60% 줄었다”라는 확대 해석을 막는 데 중요하다.

**GPT 단독 경로 길이는 성공한 문제의 구성에 좌우된다.** 이번 주 통계는 유효 경로만 포함한다. Few-shot은 69개, CoT는 110개, RePE는 114개뿐이다. 성공한 문제가 달라진 상태에서 평균 길이가 줄었다고 전체 경로 계획이 개선됐다고 볼 수 없다. 파싱 가능한 실패 경로까지 포함하면 각각 83.79%, 155.02%, 189.09%가 된다. 장애물을 가로지르는 지름길도 짧을 수 있으므로 짧은 길이만으로 품질을 판단하면 안 된다. 이 문제는 GPT 결합 조건에서는 모든 경로가 유효하므로 동일하게 적용되지 않는다.

**프롬프트 예시 중복 5개가 주원인일 가능성은 낮다.** 중복을 제외해도 Few-shot 연산량은 40.2945%에서 40.2866%로 거의 같다. CoT와 RePE도 큰 변화가 없다. 다만 이것은 정확히 같은 문제 5개의 영향을 확인한 것이며 모델 사전학습 데이터의 중복 여부를 검증한 것은 아니다.

**고전 탐색 비교군의 재현 오차는 작다.** Dynamic weighted A*는 논문 60.91% 대비 이번 60.9026%의 연산량을 보인다. 저장된 검증 로그에는 저자 탐색 구현과 15개 문제씩 지표 일치, A*와 Dijkstra의 20문제 길이 일치가 기록돼 있다. 이는 단순한 맵·비용 설정 차이가 주원인이라는 설명을 약하게 만든다. 단, Dynamic weighted A* 세부 규칙은 재구성됐고 검증도 일부 문제에 한정되어 논문 당시 파이프라인 전체와의 동일성을 보증하지 않는다. A*가 100%라는 사실 자체는 정규화 결과여서 구현 검증 근거가 아니다.

## 보고서에서 사용할 해석과 추가 검증

> 본 재현에서는 GPT 결합 탐색의 연산량 및 저장량 비율이 논문보다 낮게 나타났다. 그러나 경유점을 제거한 동일 탐색의 성능이 세 GPT 결합 조건을 집계 지표에서 상회했고, Few-shot의 50.8%는 실제 중간 경유점 없이 동작했다. 따라서 관찰된 효율 향상을 GPT의 공간 추론 능력 향상이나 경유점 품질 개선에 직접 귀속할 수 없다. 현재 데이터는 목표 지향 휴리스틱과 생성·후처리된 경유점 분포의 영향을 뒷받침한다. 논문과의 격차에 대한 정확한 기여도는 원 실험의 응답 및 실행 설정이 있어야 분리할 수 있다.

가장 가치 있는 후속 검증은 저자 응답을 확보해 동일 탐색기에 넣는 것이다. 그다음으로 같은 모델에서 줄바꿈 stop 유무만 바꾸는 실험, 같은 문제에서 여러 번 생성해 변동성을 측정하는 실험이 필요하다. 휴리스틱 가중치와 경유점 유도항을 분리한 대조군, 총 실행시간과 API 비용도 함께 측정하면 효율 향상의 실질적인 의미를 확인할 수 있다. 이번 분석에서는 새 API 요청을 실행하지 않았다.

- [분석 수치](performance_analysis.json)에는 조건별 집계, 같은 문제의 비교, 하위 집단, 신뢰구간, 입력 파일 해시가 있다.
- [문제별 비교 CSV](performance_paired.csv)에는 3,000개 문제·프롬프트 조합의 경유점 수와 제거 조건 대비 비율이 있다. CSV 비율은 백분율이 아닌 배수다.
- 원문 응답의 요청 해시·모델·설정, 파싱 결과와 경유점 필터 결과를 대조했다. 집계 행이 개별 평가 파일과 일치함을 확인했으며, 재현 코드 6개 파일의 해시는 기존 [검증 기록](../verification.json)과 일치했다.
- 탐색을 다시 실행한 검증은 아니다. 기존 경유점 제거 캐시는 입력 해시를 이번 분석에서 기록했지만, 생성 당시의 별도 실행 서명을 포함하지 않는다. 따라서 저장 결과의 내부 일관성과 기존 코드·검증 기록을 근거로 해석한다.
