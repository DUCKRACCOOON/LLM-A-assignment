# S2 결과 보고서 · 구체적인 오류 피드백으로 경로 수정

**GPT 출력 유효율은 소폭 높아졌지만, 같은 호출 횟수의 일반 재검토보다 최종 탐색량이 일관되게 줄지는 않았다.** 기존 `E2F/E2C`의 2026-10-14 완료 결과다.

## 수정 전후와 호출 비용

각 프롬프트에 동일한 1,000문제를 평가했다. [본실험 CSV](../../results/improvements/report/main_table.csv)의 GPT-only 유효율과 하이브리드 지표를 분리해 읽는다.

| 항목 | Few-shot | CoT | RePE |
| --- | ---: | ---: | ---: |
| 최초 GPT 출력 유효율 | 6.3% | 9.4% | 11.9% |
| 일반 재검토 E2C 출력 유효율 | 9.7% | 10.4% | 12.4% |
| 오류 피드백 E2F 출력 유효율 | 9.9% | 11.9% | 13.7% |
| 무효 최초 출력·추가 호출 수/arm | 937 | 906 | 881 |
| 최초+수정 논리 호출 수/arm | 1,937 | 1,906 | 1,881 |
| E2F/E2C heap-pop 감소율 | +0.36% | −0.48% | −0.78% |

마지막 행의 음수는 증가다. 최초 응답을 공유했으므로 각 arm의 논리 호출 수를 단순 합산해 실제 API 수집 수라고 보고하지 않는다.

## 최종 탐색 결과

아래는 같은 문제의 A* 대비 기하평균(%)이다. 각 행의 최종 반환 경로는 1,000/1,000 유효했지만 GPT 출력의 유효율과는 다른 결과다.

| 조건 | 연산 % | 저장 % | 길이 % |
| --- | ---: | ---: | ---: |
| E2C Few-shot | 45.16 | 65.31 | 102.36 |
| E2F Few-shot | 45.00 | 65.33 | 102.35 |
| E2C CoT | 55.56 | 73.88 | 102.76 |
| E2F CoT | 55.82 | 74.09 | 102.63 |
| E2C RePE | 76.37 | 89.38 | 102.43 |
| E2F RePE | 76.97 | 89.72 | 102.39 |
| N: g+2h 공통 | 34.32 | 56.23 | 102.02 |

확대 100조건에서도 E2F 연산 비율은 A* 대비 **55.40%**, E2C는 **54.76%**로 오류 피드백 쪽이 소폭 많았다. E2F의 저장·길이 비율은 **60.46%·102.07%**, 반환 경로 유효율은 100%였다. [대응 비교](../../results/improvements/report/paired_comparisons.csv)와 [확대 표](../../results/improvements/report/scaling_table.csv)에 전체 수치가 있다.

## 실패·실행 이력·해석

오류를 알려 줘도 수정 출력의 대부분은 여전히 무효였다. 파싱·경계·충돌 오류는 원본 `e2`의 `evidence`와 `raw` 요청·응답으로 추적한다. 최종 하이브리드 탐색 성공을 GPT 수정 성공으로 해석하지 않는다. 길이도 최단 보장이 아니다.

API 크레딧 소진으로 E2 확대가 중단됐다가 충전 후 같은 고정 코드로 남은 21문제를 채웠다. 좋은 출력으로 재생성하지 않았으며 [실행 예외 기록](../../results/improvements/execution_deviation.json)을 보존했다. S1~S3 공유 묶음 전체는 28,270행·실제 응답 8,814건으로, S2 단독 규모가 아니다.

[서버 검증](../../results/improvements/verification.json)과 [로컬 검증](../../results/improvements/local_import_verification.json)을 근거로 기존 자료를 정리했다. 유의성 검정·독립 미관측 검증·실제 서비스 지연시간 우위는 확인하지 않았다. 현 자료는 오류 피드백의 일관된 탐색 개선을 지지하지 않는다. 최초 구현·실험자는 승민이며 이번 작업은 문서화다.
