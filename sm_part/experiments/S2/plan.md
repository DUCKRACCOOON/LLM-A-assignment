# S2 계획서 · 구체적인 오류 피드백으로 경로 수정

## 목적과 기존 계획

최초 GPT 경로가 무효일 때 **검증기의 구체적 오류를 알려 주는 한 번의 수정**이 같은 호출 횟수의 일반 재검토보다 유용한지 평가한다. 이 문서는 [2026-10-14 고정 프로토콜](../../results/improvements/protocol.json)과 구현을 정리한 것으로 새로운 사전등록이 아니다.

`diagnosis`는 고정 파서·검증기에서 처음 발견한 오류를 반환한다. 파싱 오류는 설명, 시작·목표 오류는 관측값과 요구값, 범위 오류는 첫 좌표와 인덱스, 충돌 오류는 첫 경로 선분·장애물 선분과 인덱스를 제공한다. 여러 오류 중 유리한 것을 골라 반복해서 고치지 않는다.

1. E1·B와 동일한 최초 응답을 사용한다.
2. 최초 경로가 유효하면 추가 호출 없이 사용한다.
3. 무효이면 `E2F`에는 구체적 외부 검증 결과, `E2C`에는 `Not provided.`를 넣고 각각 정확히 한 번 수정하게 한다.
4. 두 조건 모두 같은 기존 문제·이전 응답·수정 요청문을 사용한다. 두 번째 답을 무조건 채택하고 더 좋은 답을 고르지 않는다.
5. 재검토 호출 순서는 지도·문제·프롬프트 인덱스에 따라 결정적으로 교대한다.

관련 구현은 [improve_core.py](../../reproduction/improve_core.py)의 `diagnosis`, `correction_payload`와 [improve_run.py](../../reproduction/improve_run.py)의 `feedback`이다.

## 통제·지표

본실험은 원본 100지도·1,000문제 각각에 standard(Few-shot)·cot·repe를 적용한다. pilot 10문제, 확대는 seed 240702511의 10문제를 1~10배로 변환한 standard 100조건이다. 모델은 `gpt-3.5-turbo-0125`, temperature 0, max_tokens 1000이고 기존 8방향 이동·충돌 규칙을 유지한다.

주 비교는 **E2F/E2C**, 보조 비교는 최초 응답을 사용하는 B와 GPT 없는 N이다. GPT 출력의 파싱·유효성과 최종 탐색 경로의 유효성을 별도 집계한다. 중복 포함 heap-pop, `len(g)`, 반환 길이, API 호출 수, 최초 오류 유형, 수정 여부, 응답 해시와 지연시간을 보존한다. 최초 호출 및 추가 호출 비용을 모두 기록한다.

대응 비율은 기하평균으로 보고하고, 이번 기존 실행에는 신뢰구간이나 독립 반복이 없음을 명시한다. 조건 간 공유로 실제 수집 호출 수와 각 알고리즘의 논리 호출 수가 다르다. 캐시 시간으로 온라인 응답시간을 대체하지 않는다.

## 실행·현재 확인 상태

Linux/Python 3.12.3의 [실행 환경](../../results/improvements/environment.json)을 기준으로 한다. `sm_part`에서 자료를 복원한 뒤 다음 명령은 기존 결과를 집계한다.

```text
python reproduction/improve_run.py report
```

새 API 응답 수집 CLI는 `python reproduction/improve_run.py all --workers 8`이며 이번 정리에서는 실행하지 않았다. 원본 결과를 보존한 별도 복사본에서만 재실험한다. 동일 호출 대조군, 한 번 수정, 수정 전후 유효율과 추가 호출 기록은 확보돼 있다. 실제 서비스의 비용·시간 우위나 새 미관측 데이터에서의 효과는 별도 검증이 필요하다.
