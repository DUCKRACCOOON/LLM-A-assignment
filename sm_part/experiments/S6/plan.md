# S6 계획서 · 필요한 장애물의 단계적 반영

## 알고리즘과 정확성 조건

[원 사전 계획 R2](../../results/next_experiments_plan/plan.md)와 [고정 실행 프로토콜](../../results/next_search_v1/protocol_frozen.json)을 S6에 대응시킨 문서다. 전체 벽을 처음부터 처리하는 것보다 필요한 벽을 점진적으로 활성화하면 총비용을 줄일 수 있다는 가설을 평가한다.

전체 벽 B의 부분집합 S와 외곽 경계를 반영한 완화 문제를 **정확하게** 푼다. 반환 경로를 B 전체에 대해 검사해 충돌하면 새 벽을 S에 추가하고 다시 푼다. 세 번의 실패 뒤에는 전체 벽을 활성화한 정확 탐색으로 전환하므로 최대 네 회차다. 완화 문제가 도달 불가능하면 원래 문제도 불가능하다.

완화 최적 비용은 원래 최적 비용의 하한이다. 그 최적 경로가 전체 벽에서도 유효하면 같은 길이가 상한도 되어 최적성을 인증한다. 이 설명은 **매 완화 문제의 정확 풀이와 최종 전체 충돌 검증**을 전제로 한다. 벽 순위나 AI의 신뢰도가 이를 대신하지 않는다.

## 비교 변형과 모델 범위

| 변형 | 초기 활성 벽·갱신 |
| --- | --- |
| first | 내부 벽 없이 시작, 첫 충돌 벽 추가 |
| batch | 내부 벽 없이 시작, 충돌 벽 일괄 추가 |
| rule | 시작-목표 직선과 교차하는 벽, 충돌 벽 일괄 추가 |
| random | rule과 같은 수의 초기 벽을 고정 무작위 선택 |
| program | 허용된 기하 특징의 결정적 점수로 초기 벽 선택 |
| incremental | 2회 이상 풀이한 개발 질의의 비율이 10% 이상이면 LPA의 정확한 상태 갱신 비교 |

AI 생성은 제한된 네 특징의 선형 가중치만 허용한다. 특징은 직선 교차, 정규화 벽 길이, 벽 끝점을 거치는 우회 거리, 외곽 경계 부착 여부다. 존재하지 않는 벽이나 임의 Python 코드를 생성·실행하지 않는다. 원 계획은 최대 60회 제안, 실제 고정 범위는 12회다. `meta-llama/Meta-Llama-3-8B-Instruct`, BF16·greedy·batch 1, revision `8afb486c1db24fe5011ec46dfbe5b5dccdb575c2`를 사용한다. 생성은 오프라인이며 질의마다 LLM을 부르지 않는다.

주 비교는 R2/A_OCT, 추가 기여는 R1_R2/R1이다. RULE·같은 벽 수의 RANDOM과 비교해 AI 선택의 독립 효과를 확인한다. `next_refinement.py`가 모든 회차의 카운터와 시간을 합산하고 `next_incremental.py`가 간선 삭제 후 상태를 갱신한다.

## 자료·측정·판정

신규 개발 60지도·600문제(seed 26101410), 검증 60지도·600문제(26101411), 최종 200지도·2,000문제(26101412)를 사용한다. 네 지도 유형을 동일 비중으로 두고 최종 자료는 설정 고정 뒤 생성한다. 확대는 40지도·80질의×1/2/4/8배, 재사용은 20지도·목표 고정/변경×Q=1/5/10이다.

활성 벽 수·새 충돌·풀이 횟수·회차별 확장·검증 교차 횟수·fallback·준비·재풀이·복원·전체 시간을 모두 기록한다. 질의 5회 중앙값과 지도 단위 bootstrap 10,000회를 사용한다. 정확 길이 100%·무효 0은 필수이며 전체 시간 ≤0.90와 확장 ≤0.80을 목표로 한다. 벽 검사만 줄고 총시간이 늘면 탈락으로 판정한다.
