# K4 실행 전 고정 규약

2026-10-25 · 규민 담당 · gm. K3 결과를 확인한 다음 정한 독립 개선 실험이며 K4 결과에 따른 설정 튜닝은 하지 않는다.

## 가설과 구현

K3의 octile＋단일 벽 하한을 h0로 두고 f=g+h0를 계산한다. OPEN의 최소 f를 fmin이라 할 때 f≤w·fmin인 후보만 FOCAL에 넣는다. 주 설정은 **w=1.05**, 즉 최단경로보다 최대 5% 긴 비용을 허용한다. 이는 기존 g+2h의 h 가중치 2와 다른 파라미터다.

FOCAL 내부에서는 LLM이 준 polyline의 가장 가까운 투영점까지 거리와 그 투영점부터 polyline을 따라 목표까지 남은 길이의 합을 최소화한다. 투영점 거리가 같으면 목표 방향으로 더 진행한 투영점을 택한다. 동률은 h0, f, 노드 좌표 순서다. 이 보조 점수는 하한이 아니며 FOCAL 내부 순서에만 쓴다. LLM은 후보를 삭제하거나 최종 경로를 결정하지 않는다.

2차원 유한 좌표 목록을 파싱하고 시작과 목표를 양 끝에 보완한다. 길이 0 선분은 계산에서만 건너뛴다. 충돌하거나 범위를 벗어난 안내도 임의로 수리하지 않고 보조 점수에만 쓴다. schema 오류·비유한 선분 계산이면 h0 안내로 전환하고 이유를 남긴다. 유효하지 않은 안내도 탐색의 품질 제한이나 충돌 규칙을 바꿀 수 없어야 한다.

더 낮은 g가 발견되면 CLOSED 상태도 다시 연다. OPEN 최소값, FOCAL 자격, stale 항목 처리를 버전으로 관리한다. OPEN·대기 후보·FOCAL의 세 heap을 사용하고 fmin이 낮아지는 경우 자격 집합을 다시 구성한다. 실제 반환 경로를 원 충돌·8방향 이동 규칙으로 검증한다. oracle는 탐색에 전달하지 않는다.

## 데이터와 응답

- 공개 100지도×10쌍=1,000문제: K3와 동일한 입력.
- 별도 지도 10개×3쌍=30문제: 기존 `results/generalization/cases.json`, seed=20261013. **K3의 seed=20261025 새 지도 120문제와 다르다.** 실제 GPT 응답이 저장된 이 집합에서 g+2h와 K3도 다시 실행한다. 30문제는 작은 전이 점검이며 강한 일반화 근거로 보지 않는다.
- GPT-4o mini `gpt-4o-mini-2024-07-18`, Few-shot/standard, 기존 실제 응답 1,030개를 고정 재생한다. 원 요청·프롬프트 해시와 입력 일치를 확인한다. 새 API 호출과 응답 재생성은 하지 않는다.
- 공개 지도 0,10,…,90의 각 pair 0,1,2인 30문제 파일럿은 본실험의 일부다. 하이퍼파라미터를 고르는 표본으로 사용하지 않는다.

## 검증과 측정

1. K3의 독립 정수 기하·Dijkstra를 재사용한다. 1,030문제의 최단거리를 다시 구해 유효 경로와 w 제한을 확인한다.
2. 빈 지도·벽 끝점·도달 불가 등 10가지 경계 사례, 누락·잘못된·충돌하는 안내, 재개방이 필요한 그래프, fmin 감소를 검사한다. 단순한 전체 OPEN 스캔 FOCAL 참조 구현과 선택 순서를 비교한다. 고정 seed=20261026의 작은 무작위 지도 40개에서도 경로·제한·선택 순서를 확인한다.
3. 공개 g+2h·A*는 기존 저장 결과와, K3 두 변형은 이전 K3 저장 결과와 경로·operation·storage·length 일치를 확인한다. 새 엔진을 도입해 생기는 효과를 LLM 효과로 섞지 않는다.
4. 각 조건·문제를 3회, 고정 시드로 방법 순서를 섞어 한 프로세스에서 실행한다. 지도·거리·안내 캐시를 매번 새로 만든다. 파일 읽기·독립 정답 검증·기록 시간은 제외하고 지도 생성·거리 준비·안내 파싱·FOCAL 관리·검색·반환 경로 검증을 포함한다.
5. **operation은 모든 heap의 pop 합계**다. FOCAL 선택 pop만 세어 기존 단일 큐보다 유리하게 보이지 않도록 OPEN 정리·대기 후보 승격·stale 제거도 센다. 실제 선택/확장 횟수, 재확장, 모든 heap push, 재구성 스캔, 최대 heap 항목 수, 안내 선분 검사 수를 별도로 보고한다. heap pop 수는 전체 CPU 연산 수가 아니다.
6. storage는 g 사전 항목 수(무한 비용 포함)이며 전체 RAM이 아니다. 다중 heap 메모리와 안내 polyline 저장 비용을 별도 설명한다.
7. 시간은 캐시 응답이 이미 있는 **계획기 시간**이다. 실제 새 문제에는 LLM 생성 지연·비용이 더 든다. 기존 응답의 기록 지연·토큰을 별도 보존하고, 과거 지연＋현재 계획기 시간의 합은 추정치로만 표시한다.
8. 문제별 비율의 기하평균, 각 문제 시간 3회 중앙값, 지도 단위 bootstrap 2,000회·seed=20261026의 95% 구간. 실패는 전체 분모에 남기고 길이 비교 분모를 명시한다. 개별 w 제한 위반과 개선/동일/악화 건수도 보존한다.

## 근거와 완료 자료

FOCAL 틀은 [Anytime Focal Search with Applications](https://ijcai.org/proceedings/2018/199) 및 [New Results in Bounded-Suboptimal Search](https://www.cs.unh.edu/~ruml/papers/rrd-aaai-2022.pdf)의 Focal Search 설명을 참고한다. 이번 작업은 일반 FOCAL에 우리 LLM 투영 안내를 연결한 것이며 AFS·EES 전체 재현이라고 주장하지 않는다.

품질 제한은 admissible 하한, 유효한 OPEN 하한, 더 나은 g의 재개방, FOCAL 내 목표 선택이라는 조건에 근거한다. LLM의 정확도나 자기 신뢰도가 보장 근거가 아니다. 수치 오차 허용치는 1e-8이다.

새 폴더에만 입력·응답 연결·환경·코드 해시·원시 결과·통계·과정·악화 사례·선정 메모를 남긴다. 기존 재현/K3 결과, 공용 main은 변경하지 않는다. `gm`에 구현과 기록을 함께 저장한다.
