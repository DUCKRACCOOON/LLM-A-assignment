# J4 전체 데이터셋 1회 평가

2026-11-11, jy. J3 다음 J4(ALT 랜드마크 휴리스틱)를 공개100지도×10쌍=1,000문제에서 평가한다.

- 기존 JY의 LandmarkIndex와 정확 A*를 변경 없이 사용한다. 첫 랜드마크는 lexicographic 최소,
  다음은 graph-farthest 방식이다. 시작·목표·oracle 정답을 랜드마크 선택에 쓰지 않는다.
- 주 J4는4개, J4_alt8은8개 랜드마크다. h=max(octile, max_l |d(l,n)-d(l,G)|)이며 유한한 거리표 항만 사용한다.
- 대조군 Astar/LLMA/G2H/Octile/WallAstar/GraphOctile를 포함해8조건, 문제·조건별1회=8,000회다.
  GraphOctile는같은 LandmarkIndex(q,0)의 전체 합법 그래프와 같은 검색 엔진을 쓰되 거리표 없이 octile만 사용한다.
  LLMA/G2H 외6조건은 최단성을 목표로 한다. 모든 대조를 이번 실행에서 같이 측정하며 이전 결과와 합산하지 않는다.
- GraphOctile/J4/J4_alt8은 매 질의마다 실제로 전처리를 새로 생성한다. 물리적 준비3,000회다.
  전체 그래프 생성·랜드마크 선택·모든 landmark Dijkstra·이웃 캐시 정리를 전처리 시간에 포함한다.
- 전체 로컬 시간은 전처리+검색+복원+필수 검증이다. prepared_query_seconds는 전체 로컬에서 실제 전처리만 뺀 값으로
  나머지 준비·wrapper 검증도 포함한다. 쿼리 검색 시간만으로 단일 질의의 우위를 주장하지 않는다.
- 재사용은 별도 실행을 추가하지 않는 합산 시나리오다. 같은 지도에서 고정된 첫Q=1/5/10쌍에 대해
  첫 질의의 전처리1회+각 prepared_query_seconds를 합한다. 동일한 deterministic index의 랜드마크·크기·작업 카운터를 대조한다.
  각 검색은 새 index로 실제1회 실행했으며 하나의 index를 상주시켜 연속 서비스한 실측이라고 표현하지 않는다.
  10쌍을 초과하는 손익분기나 임의Q 결과를 추정하지 않는다.
- CPU/native1스레드, seed20261111로 방법 순서를 섞는다. 파일 읽기·독립 Oracle/Dijkstra·전처리 검산·집계는 타이머 밖이다.
  모든 방법의 필수 경로 검증은 안이다. 방법/질의 간 Geometry 이웃 캐시는 공유하지 않는다.
- ALT는 온라인 LLM을 사용하지 않는다. 원 LLMA 대조만 results/main의 같은 standard1,000응답을 검증 후 재생한다.
  새 API 호출0회, 실행 중 네트워크/API 연결 차단. 과거 API 지연+현재 로컬 총시간은 재구성 추정이며 현재 서비스 실측이 아니다.
- 독립 정수 Oracle로100지도 간선을 대조하고 모든 경로·정확 조건·최단거리를 검사한다.
  각 실제 index의 h를 해당 목표의 독립 최단거리와 비교하고, 각 지도 첫 질의에서 실제 준비 graph도 독립 graph와 대조한다.
  정답은 탐색기/전처리에 전달하지 않는다. GraphOctile와 같은 엔진 Octile의 경로·pop·확장·상태 동등성도 검산한다.
- operation은 전처리 heap pop+query pop이다. 실제 이웃 확장은 query와 전처리를 구분한다.
  graph 생성 비용·거리표 읽기·휴리스틱 연산을 heap pop이 전부 나타내지는 않는다. 거리표·graph 저장량도 별도 기록한다.
  논리 상태/항목은 메모리 bytes나 전체 peak가 아니며 별도 RSS 측정은 없다.
- 공개 전체는 기존 연구 노출 자료다. COMMON18 test200도 부분집합으로 구분하되 고유 문제 수에 더하지 않는다.
  시간1회이므로 반복 안정성을 주장하지 않는다. 지도 bootstrap2000회는 구성의 탐색적 구간이며 API/시간 반복 변동은 포함하지 않는다.
- 기존 구현·결과를 보존한다. 준연 담당 J4 평가에 Codex가 실행 통합·검증·분석 작성을 지원한다. J5이후는 이번에 새로 실행하지 않는다.
