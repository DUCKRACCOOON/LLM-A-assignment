# K5 실행 전 고정 규약

2026-10-25, gm. K3·K4 결과를 본 뒤 설계했고, K5 성능 측정 전에 이 설정을 고정한다. 성능에 따른 안내식·시드·가중치 변경은 하지 않는다. 구현 결함은 수정 이유를 기록한다.

## 질문과 구현 범위

여러 안내에 탐색을 배분하면 단일 K3보다 좋아지는가? 고정 순환보다 Thompson Sampling이 도움이 되는가? 그중 LLM 안내의 기여는 있는가?

Shared MHA*의 공유 g/parent, anchor 및 보조 CLOSED, 확장 자격과 종료 검사를 사용한다. anchor h0는 K3의 octile＋벽 하한이다. w1=1로 고정한다. 보조 안내는 순서대로 2h0, 2×목표 직선거리, 2×K4 LLM polyline 점수다. LLM 응답 파싱 실패 시 마지막 안내를 2h0로 대체하고 실패 이유를 보존한다. 안내 수를 불리한 결과에 맞춰 늘리거나 줄이지 않는다.

주 방법 `mha_dts_w200`은 w2=2, 즉 비용 상한 2×최적비용을 사용한다. 기존 g+2h와 같은 2배 상한 수준에서 속도를 겨룬다. 단, 기존 구현의 CLOSED/중복 처리까지 같다는 뜻은 아니다. K4 주 설정과 같은 5% 상한은 별도 `mha_dts_w105`로 비교한다. 이 차이를 숨기고 두 방법의 속도를 직접 승패로 해석하지 않는다.

각 큐의 우선순위는 g+hi, 동률은 좌표 순서다. 보조 큐 최솟값이 w2×anchor 최솟값 이하일 때만 그 큐를 확장한다. 그렇지 않으면 anchor를 확장한다. 목표의 g가 선택 큐의 최솟값 이하이면 종료한다. 확장한 노드는 모든 큐에서 제거한다. anchor에서 확장한 노드는 재확장하지 않고, 보조에서 확장한 노드는 g가 낮아진 경우 anchor에서만 다시 확장할 수 있다. 보조 삽입 조건은 key_i≤w2×key_0이며, g 변경으로 조건을 잃은 기존 항목도 무효화한다.

DTS는 매 문제 α=β=1로 초기화하고 Beta 표본이 가장 큰 보조 큐를 선택한다. 해당 큐의 실제 확장 이후 OPEN_i의 최소 hi가 과거 최저보다 작으면 보상 1, 아니면 0이다. anchor로 대체된 선택에는 보상을 주지 않는다. α+β가 C=10을 넘으면 둘을 C/(C+1)배로 줄인다. 정답 경로, 미래 확장량, LLM의 자기 신뢰도는 사용하지 않는다. 보상용 최소 hi도 별도 heap으로 관리하고 비용에 포함한다. 보조 선택이 실패해도 anchor가 진행하므로 TS의 통계적 성공이 탐색 완전성의 전제는 아니다.

### 본실험 전 검증 수정 기록

첫 경계 검증에서 목표를 여러 번 지나는 잘못된 polyline은 부동소수 투영 오차로 목표의 안내 값이 0이 아닐 수 있었다. MHA의 전제에 맞춰 LLM 보조 안내도 목표에서는 명시적으로 0으로 둔다. 그 외 점수와 K4 구현은 바꾸지 않는다. 이 수정은 성능 측정 전의 정확성 보완이다.

## 입력과 반복

- K4와 같은 공개 1,000문제 및 기존 별도 지도 30문제. 별도 30개는 seed=20261013이며 K3의 추가 120문제와 다르다. 재사용한 평가 집합이므로 완전히 미지의 holdout이라고 부르지 않는다.
- K4와 동일한 실제 GPT-4o mini 2024-07-18, standard/Few-shot 응답 1,030개. 원 요청과 입력의 일치·해시를 검증한다. 새 API 호출 0회.
- 확률 조건은 문제당 **5개 고정 시드**, 각 시드 **시간 측정 3회**. 시드는 SHA256("K5|20261027|case_id|seed_index") 앞 8바이트로 결정한다. 알고리즘 이름이나 실행 순서에 의존하지 않는다. 문제 간 학습은 없다.
- 결정적 조건은 시간 측정 3회. 총 조건 13개, 문제당 87회 실행. 같은 시드 3회의 경로와 모든 핵심 지표가 같아야 한다.
- 순서 무작위화·bootstrap seed=20261027. 공개 지도 0,10,…,90의 pair 0,1,2 총 30문제 파일럿 후 본실험. 파일럿은 검증용이며 튜닝이나 독립 성능 근거로 쓰지 않는다.

## 검증·측정·집계

1. 독립 정수 기하/Dijkstra로 경로·실제 최적비용·비용 상한을 검사한다. oracle는 탐색에 제공하지 않는다. 작은 그래프와 고정 무작위 지도에서 heap 없는 집합 기반 SMHA 참조와 순서·결과·보상 상태를 비교한다. 잘못된 안내, 도달 불가, start=goal, CLOSED 구분, 동일 시드 재현, DTS 이력 축소도 검사한다.
2. 모든 비교군의 경로·길이·operation·storage를 이전 K4 원시 기록과 대조한다. 예전 시간 수치를 섞지 않고 함께 재측정한다.
3. operation=탐색 heap과 **보상 heap까지 모든 pop 합계**. 별도로 실제 이웃 확장 횟수(successor_expansions), 탐색 pop, 보상 pop, stale, push, 최대 전체 heap 항목, 큐별 선택·확장·보상·anchor 대체 횟수를 기록한다. MHA는 목표를 pop하기 전에 종료하므로 이웃 확장은 목표를 제외해 모든 방법에서 맞춘다. pop은 전체 CPU 명령 수가 아니다.
4. storage는 g 사전 크기이며 전체 RAM이 아니다. blocked 이웃의 inf 항목 포함. 준비·안내 파싱·캐시 생성·큐와 bandit 관리·탐색·반환 경로 검증은 계획기 시간에 포함한다. 파일 IO·독립 oracle·기록·전역 geometry 캐시 비우기는 제외한다. 매 실행 새 인스턴스다.
5. 시간은 각 시드의 3회 중앙값. 확률 조건의 주 집계는 문제별 5시드 **산술평균** 후 대조군과의 비율을 계산하고 문제 간 기하평균을 낸다. 최고 시드만 선택하지 않는다. 시드별 전체 비율 범위도 별도 기록한다. 지도 단위 bootstrap 2,000회의 95% 구간은 고정 5시드 평균에 조건부이며 seed 불확실성 전체를 포괄한다고 주장하지 않는다.
6. 성공/경로 상한/최적 경로 비율은 5시드 각각 검사하며 분모를 명시한다. 실패를 제외하고 성공률을 부풀리지 않는다. 실패 시 원시 기록부터 저장하고 검증을 중단한다.
7. 응답 생성은 캐시 재생이다. 과거 API 지연 및 토큰을 별도 기록하고 계획기 속도를 온라인 전체 지연으로 주장하지 않는다. 반복별 원시 결과는 무손실 gzip JSONL로 보존한다.

## 출처와 해석 한계

[Aine et al., Multi-Heuristic A*, RSS 2014, Fig. 3](https://publications.ri.cmu.edu/storage/publications/pub_files/2014/7/rss14.pdf)의 SMHA*와 [Phillips et al., Efficient Search with an Ensemble of Heuristics, IJCAI 2015, Algorithms 1/4](https://www.cs.cmu.edu/~venkatrn/papers/ijcai15.pdf)의 DTS를 참고한다. C=10은 후자의 로봇 실험 설정에서 가져왔다. 이 과제에 더 좋은 값이라는 근거는 없다. 안내 함수·지도·가중치·소수 큐는 우리 적용이며 이 두 연구의 실험 전체를 재현하는 작업이 아니다. TS의 보상은 최종 경로/속도의 대리 지표다. 특히 공유 OPEN의 진전을 특정 큐에 귀속하는 한계가 있다.

정확한 충돌과 일관된 anchor, SMHA의 삽입·확장·종료 조건을 유지해야 비용 제한을 기대할 수 있다. 코드에서는 1e-10 비교 여유, oracle 검증에서는 1e-8을 쓴다. 성능 향상은 보장하지 않는다. 이전 결과·원본 코드·main을 수정하지 않고 gm의 K5 코드·검증·원시 결과·설명·AI 지원 기록을 보존한다.
