# 18개 방법군 동일 조건 비교 — 실행 전 규약

2026-10-28 (Asia/Seoul), jy. 기존 결과와 별도 run_20261028에 기록한다.
사용자는 서로 다른 브랜치의 18개 방법을 동일 조건으로 비교하라고 요청했다.
목표는 LLM-A* 대비 실제 개선과 비용/정확성의 절충을 확인하는 것이다.

## 고정 입력·모델·예산

- 원 공개 100개 지도의 동일한 8방향 격자/닫힌 선분 충돌/1,√2 비용을 사용한다.
- sm candidates의 seed=261014 지도 분할을 유지한다. 예시 지도 [0,2,3,4,5]는 train에 강제 배치,
  나머지 95개를 random.Random(261014)로 섞어 train45/validation10/calibration20/test20을 나눈다.
  20 test 지도×10쌍=200문제를 모든 방법에 동일 적용한다. 기존 실험에 이미 노출된 공개 자료다.
- S4는 sm의 seed11, best epoch35 모델을 변경 없이 CPU로 가져온다. train/validation/test 분리와
  체크포인트 SHA-256을 확인한다. 새 학습이나 모델 선택을 하지 않는다. 로딩·warm-up 시간은 별도다.
- 모든 온라인 LLM은 gpt-4o-mini-2024-07-18, temperature0. 기본 standard/CoT/RePE max_tokens1000,
  S2 수정1000, K1 ID 순위256. 기존 프롬프트를 사용하며 문제별 성공을 위한 재생성은 없다.
- 같은 일자의 새 응답을 공유한다. calibration200+test200의 세 프롬프트 최대1200회,
  test의 S2 오류 수정 최대200회, K1 순위 최대200회, 합계 신규 HTTP 요청 최대1600회.
  병렬 수집 최대4개, 전송 자동재시도 없음. API 오류는 저장 후 중단한다. 재개는 동일 요청 SHA만 재사용한다.
  누적 사용량 안전 상한 input 5,000,000 / completion 1,600,000 tokens. 청구 금액은 추정하지 않는다.
- 자격증명은 원 로컬 .env 또는 환경변수에서 메모리로만 읽고 파일/로그/ZIP에 복사하지 않는다.

## 조건

18개 primary: K1 통로 ID(w=1.05), K2 Conformal(w=1.05), K3 직선거리+벽 g+2h,
K4 LLM FOCAL(w=1.05), K5 MHA+DTS(w=1.05), K6 적응 α(w=1.05), J1 CHOMP(w=1.05),
J2 FMM+LLM(w=1.05), J3 LLM 초기 해+정확 BB, J4 ALT4, J5 NBS octile, J6 lazy,
S1 경유점 정제, S2 구체 오류 피드백, S3 정체 시 호출, S4 자체 TransPath(w=1.05),
S5 sparse 직사각형 압축, S6 program 점수 [0.5,0.3,0.1,0.1] 장애물 단계 반영.

원래 대표 조건에서 K1/K2/K5/K6/J1/J2/S4의 허용 배율을 공통 1.05로 맞춘 변형이다.
원 결과를 대체하지 않는다. S1/S2/S3/J6/원 LLM-A*는 같은 품질 상한 보장이 없으므로
18개 전체 시간만으로 동등한 품질에서 최속이라고 주장하지 않는다.

기본 비교군: 원 A*, 원 LLM-A*, g+2h, sm-native LLM-A*, clean octile A*.
기여 분리: K1 RULE/RANDOM, K2 기본 FOCAL, K4 no-guide, K5 no-LLM,
K6 no-guide 동일 w1.05, J1 직선 초기화, J2 uniform FMM, J3 비LLM 초기 해,
J6 full, S4 untrained. 일부 동일 조건은 한 비교군을 공유한다.
정확 비교: J3, J4, J5, S5, S6, K4(w=1)와 원 A*. LLM 사용 정확 후보는 J3와 K4(w=1)를
같은 실행 블록에서 비교한다. 일부 비LLM 행은 공통 대조용이며 과제의 주 개선안으로 자동 선정하지 않는다.
K5 확률성은 각 문제에 seed=20261028로 고정한 별도 3시드의 시간3회. 독립 문제 수를 늘리지 않는다.

## 측정·검증

- CPU 한 프로세스, native 스레드1, 방법 순서를 고정 seed=20261028로 섞는다.
  각 문제 3회 반복. 입력/응답 디스크 읽기는 측정 전, 지도 준비·탐색·복원·유효성 검사는 포함한다.
  ALT 등 전처리를 단일 질의마다 포함하며 다른 방법과 캐시를 공유하지 않는다.
- LLM은 한 번 생성 후 동일 응답을 각 방법/반복에 재생한다. local_seconds와 api_seconds,
  둘의 합인 reconstructed_total_seconds를 분리한다. 후자는 각 방법을 따로 온라인 동시 실행한
  실측 서비스 시간이 아니며, 같은 수집 조건의 응답 지연을 이용한 비교 추정이다.
  3개 프롬프트가 필요한 방법은 순차 호출 배포를 가정해 지연을 합한다. 병렬 배포 시간으로 해석하지 않는다.
- 호출수/입출력 토큰/응답 오류/finish_reason을 기록한다. 무효 안내도 삭제하지 않는다.
- pop·실제 이웃 확장·저장 상태·OPEN peak가 제공되는 경우 기록한다. 출처 엔진에 해당 카운터가
  없으면 추정해서 채우지 않는다. 압축/FMM/ALT의 전처리 비용과 모든 반복 탐색을 포함한다.
- 독립 정수 orientation 기반 Oracle로 전체 test 지도 간선을 대조하고 문제별 Dijkstra 정답을 구한다.
  정답은 평가와 Conformal의 calibration에만 사용하고 온라인 안내에 전달하지 않는다.
- 같은 격자의 서로 다른 backend 벡터 간선과 SM 원 World 충돌을 모두 독립 graph에 대조한다.
  모든 반환 경로·비용 상한·정확 조건의 최단거리를 검사한다. 실패 행도 먼저 저장한다.
- 시간 반복 중앙값, 문제별 방법/원 LLM-A* 비율 기하평균, 지도 bootstrap2000회95%구간,
  성공률/최단 일치/최대 및P95경로초과, 개선/악화 건수, 전체 합계를 함께 보고한다.
- 별도 동일 10문제(각 test 지도의 첫 문제 중 map index 작은10개)에서 방법별 격리 subprocess의
  RSS를 1ms 간격으로 샘플링한다. Python/라이브러리/모델 상주분을 포함한 process peak이며
  순수 알고리즘 할당량/순간 peak를 보장하지 않는다. 시간 결과와 혼합하지 않는다.
