## 무엇을 바꿨나

기존 `g+2h`의 h는 목표까지의 직선거리다. 목표가 벽 바로 건너편이면 가까워 보이므로 막힌 벽 주변을 많이 탐색할 수 있다. K3는 그 벽을 돌아가는 데 필요한 거리도 고려한다. **탐색의 목표, 가중치 2, 큐의 동률 처리, CLOSED와 중복 pop 처리, 충돌·격자 이동 규칙은 동일하다.** 기존 코드는 [search](../../reproduction/core.py)의 선택적 `goal_heuristic` 인자만 추가했으며 기본 동작은 유지했다.

현재 노드 n에서 목표 G까지의 직선이 벽 j와 만나면, 벽 끝점 a, b를 사용한다.

```text
wall_j(n) = min(distance(n,a)+distance(a,G), distance(n,b)+distance(b,G))
octile(n) = max(dx,dy) + (sqrt(2)-1)*min(dx,dy)
h_K3(n)   = max(octile(n), wall_1(n), ..., wall_m(n))
priority  = g(n) + 2*h_K3(n)
```

직선과 만나지 않는 벽의 하한은 직선거리여서 최댓값에 별도로 넣지 않아도 된다. 벽별 거리를 **합산하지 않는다**. 같은 우회를 여러 번 세는 오류를 피하기 위해 가장 강한 하한 하나의 값을 취한다. 노드에서 목표를 잇는 선과 모든 고정 벽을 비교하며 벽의 순서나 성능에 따라 일부만 고르지 않는다.

예를 들어 시작 (2,4), 목표 (10,4), 수직 벽 x=6·y=1..7이면 직선거리는 8이다. 벽의 위나 아래 끝으로 돌아가는 연속 거리 하한은 5+5=10이다. 실제 8방향 격자에서는 벽 끝도 밟을 수 없어 최단거리가 약 11.314다. K3는 여기서 10을 사용한다. 실제 경로를 끝점 경유로 강제하지 않으며, 11.314라는 정답을 탐색에 전달하지도 않는다.

## 하한이 되는 이유와 보장의 범위

벽 하나만 남기고 나머지 벽, 바깥 경계, 격자 방향 제약을 없앤 문제는 원래 문제보다 쉽다. 이 완화 문제에서 직선이 막혔을 때 가능한 최단거리의 하한은 두 끝점 중 하나를 도는 거리다. 끝점 접촉을 허용하는 것은 하한 계산에서만 적용한다. 실제 탐색은 모든 벽에 대한 접촉 금지를 유지한다.

octile도 장애물이 없는 8방향 격자의 정확한 거리여서 하한이다. 여러 하한의 최댓값 역시 하한이다. 각 완화 문제의 거리 함수는 실제 합법적인 간선을 따라 삼각부등식을 만족하고, 고정된 함수들의 최댓값도 일관성을 유지한다. 독립 그래프의 모든 합법적 간선에서 이 조건을 수치 검증했다.

**h가 하한이어도 2h는 하한이 아니다.** 주 방법은 가중 탐색이므로 최단경로나 모든 문제에서의 개선을 약속하지 않는다. 비가중 `g+h_K3`는 정확성 확인용으로만 실행했다. 이 실험은 상·하한이 있어야 하는 후속 K4의 구성요소 평가로 활용할 수 있지만 K4 자체를 구현한 것은 아니다.

## 다시 실행하기

저장된 결과를 열어보는 데는 모델·키·GPU가 필요 없다. 아래 명령은 LLM/API를 호출하지 않는다. 탐색·검증은 Python 표준 라이브러리, 통계는 NumPy, 그림은 Matplotlib을 쓴다. 실제 사용 버전은 결과 문서와 manifest에 기록한다.

저장소 루트에서 `gm` 브랜치인지 확인한 뒤 **존재하지 않는 새 폴더**를 지정한다.

```powershell
python -m experiments.K3.run --output experiments/K3/results/recheck_01
python -m experiments.K3.report --input experiments/K3/results/recheck_01
```

실행 순서는 경계 사례 → 합성 지도 고정 → 전체 하한·경로 검증 → 30문제 파일럿 → 공개 1,000문제 → 합성 120문제다. 파일럿은 전체 평가에 포함되는 사례여서 독립적인 표본 수에 더하지 않는다. 동일 폴더로 재실행하면 기존 측정 덮어쓰기를 막기 위해 중단한다.

간단한 호출은 다음과 같다.

```python
from experiments.K3.heuristic import run_once

# query: 원 재현과 같은 start/goal/range/barrier 사전
baseline = run_once(query, 'g2h_euclidean')
k3 = run_once(query, 'g2h_wall_euclidean')  # 최종 선택: 직선거리＋벽 하한
print(baseline['operation'], k3['operation'])
print(baseline['length'], k3['length'])
```

`run_once`는 타이밍을 위한 단일 프로세스 실험용 함수다. 시험 사이에 원본 Geometry의 전역 lru_cache를 비우므로 병렬 요청용 서비스에 그대로 쓰지 않는다. 캐시를 지우는 시간은 두 방법 모두 측정에서 제외한다.

## 결과 파일 읽는 법

`results/run_20261025/` 안의 파일은 다음 역할을 한다.

| 파일/폴더 | 내용 |
| --- | --- |
| manifest.json | 실행 명령·시각·환경·기준 커밋·입력 SHA-256·완료 여부 |
| fixtures.json | 손으로 점검하는 10가지 경계 사례와 방법별 결과 |
| public_cases.json, synthetic_cases.json | 평가 입력 전체, 합성 지도의 시작·목표 포함 |
| synthetic_sampling.json | 크기·벽 수·시작/목표 표본 추출 제외 사유 |
| verify_public/, verify_synthetic/ | 독립 Dijkstra 정답, 하한성·일관성·충돌 동등성 검사 |
| pilot/, public/, synthetic/ | 각 평가의 원시 측정·문제별 집계·통계 결과 |
| */evaluations.jsonl | 문제×5방법×3반복 원시 경로·시간·연산 수·벽 검사 수 |
| */per_case.csv | 같은 문제의 반복 시간을 중앙값으로 집계한 표 |
| */summary.json | 유효율, 절대 평균, 상대 기하평균과 지도 bootstrap 구간, 개선/악화 건수 |
| */checks.json | 기존 저장 결과 동등성·경로 유효성·반복 수 검사 |

`operation`은 원 코드의 **중복을 포함한 큐 pop 횟수**다. 벽 검사 등 모든 계산을 센 숫자가 아니다. `storage`도 원 코드의 g 사전 크기(무한값 포함)이며 프로그램 전체 메모리가 아니다. K3는 벽 정보 O(벽 수)를 추가 저장한다. 벽 검사 횟수와 총시간을 함께 확인해야 한다.

총시간은 지도 구조 생성, 벽 끝점과 목표의 거리 준비, 탐색, 반환 경로 검증을 포함한다. 독립 Dijkstra는 정답 검증용이므로 온라인 탐색 시간에 포함하지 않는다. 모든 방법에 정답 그래프를 전달하지 않으며 전처리·캐시를 문제 사이에 재사용하지 않는다. 원시 로그 쓰기와 통계도 제외한다.

## 출처와 작업 기록

탐색 골격은 MIT 라이선스 [원본 연구 코드](../../UPSTREAM.md)를 기존 재현에서 옮긴 것이다. K3의 벽별 완화와 octile 최댓값 결합은 [이전 조사 문서](../../최신/V-Gate_이후_개선_방법_조사.md)에 명시한 적용 설계다. 다른 논문의 알고리즘 전체를 그대로 재현했다고 주장하지 않는다.

K3 신규 구현·실험·문서는 규민 담당 작업에서 Codex의 코드 작성과 분석 지원을 받아 수행했다. 승민의 기실험 자료를 K3 결과로 재사용하지 않았다. 팀원별 실제 기여와 AI 지원은 최종 보고서에서 사실대로 구분한다. 이 폴더는 개인 브랜치 `gm`의 기록이며 공용 `main`에 실험 파일을 추가하지 않는다.
