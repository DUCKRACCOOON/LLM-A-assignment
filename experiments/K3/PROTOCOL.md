# K3 실행 전 고정 규약

2026-10-25. 개인 작업 브랜치 gm. 모델 호출 없이 기하학적 하한만 평가한다.

## 변경 범위와 가설

고정 가중치 2의 동일 탐색 엔진에서 목표 거리 h만 바꾼다. 원본의 8방향 이동, 선분 접촉 충돌, CLOSED 처리, 동률 순서, 중복 pop과 무한 g 항목은 유지한다. `reproduction.core.search`에는 선택적 거리 함수 인자만 추가하며 기존 호출의 기본값은 바꾸지 않는다.

K3는 벽 하나를 제외한 장애물·경계·격자 방향 제한을 제거한 완화 문제의 거리와 기본 거리의 최댓값이다. 벽 끝점 접촉 허용은 하한 계산에만 사용한다. 모든 고정 벽을 검사하며 학습한 가중치나 지도별 설정은 없다.

주 가설은 벽을 고려한 하한이 불필요한 탐색을 줄이는지 여부다. 하한 강화 자체가 가중 탐색의 연산량·경로 길이·시간을 모두 개선한다는 보장은 없다. 가중치 2를 사용하므로 최단 경로 보장을 주장하지 않는다. LLM이 없는 구성요소 평가이며 LLM의 기여를 증명하는 실험은 아니다.

## 고정 비교 조건

| 코드 | 조건 | 목적 |
| --- | --- | --- |
| astar_euclidean | A*, 직선거리 | 원 재현 기준·최단거리 참조 |
| g2h_euclidean | g+2h, 직선거리 | 핵심 대조군 |
| g2h_octile | g+2h, 8방향 octile | 기본 거리 변경 효과 분리 |
| g2h_wall_euclidean | g+2h, 직선거리와 벽별 하한의 최댓값 | 벽 정보만 추가한 대조 |
| g2h_wall_octile | g+2h, octile과 벽별 하한의 최댓값 | 사전 지정 주 방법 K3 |

별도로 비가중 `astar_wall_octile`을 정확성 검증에 사용한다. 결과가 좋은 변형을 사후 주 방법으로 바꾸지 않는다.

## 검증과 데이터

1. 손으로 확인할 수 있는 빈 지도, 단일 벽, 역방향 벽, 교차 벽, 경계 연결 벽, 퇴화 벽, 동일 시작·목표, 도달 불가 사례를 검사한다.
2. 독립적인 정수 선분 교차 판정으로 격자 그래프를 구성한다. 목표에서 역방향 Dijkstra로 실제 거리를 구하고 각 도달 가능한 노드에서 하한성, 각 합법적 간선에서 일관성을 검사한다. 검증용 정답 계산은 온라인 탐색에 전달하지 않는다.
3. 공개 100개 지도 ×10쌍 =1,000문제를 모두 평가한다. 기존 저장 A*와 g+2h의 경로·operation·storage·length와 기본 호출의 동등성을 확인한다.
4. 파일럿은 공개 map 0,10,...,90의 pair 0,1,2인 30문제다. 설정을 고르기 위한 성능 튜닝에 사용하지 않으며 전체 평가의 일부다.
5. 추가 지도는 seed=20261025, 30개 지도 ×4쌍 =120문제로 고정한다. 크기는 (32,22),(52,32),(72,42)를 순환하고, 수평·수직 벽 수는 각각 4·6·8을 순환한다. 벽의 양 끝과 위치는 코드의 고정 규칙으로 생성한다. 서로 다른 유효 시작·목표 중 연결된 쌍을 채택하며 모든 제외 건수를 기록한다. 기존 공개 지도와 분리된 합성 평가이며 광범위한 일반화 보장은 아니다.

## 측정

- 방법별 각 문제를 3회 실행한다. 반복별 방법 순서를 고정 시드로 섞고 한 프로세스에서 순차 실행한다.
- 매 실행마다 Geometry·이웃 캐시·거리 캐시를 새로 사용한다. 총시간은 Geometry 생성, 벽 끝점 거리 준비, 탐색과 반환 경로 검증을 포함한다. 파일 읽기·쓰기, 통계·정답 검증, 시험 간 캐시 제거는 측정에서 제외한다.
- 각 반복의 원시 시간과 지표를 보존하고, 문제별 3회 시간의 중앙값을 집계한다. 실행 환경에 종속된 측정이다.
- operation은 중복 포함 pop 수, storage는 무한 g 포함 사전 크기다. 벽 검사 수와 휴리스틱 평가 수도 별도로 기록한다.
- 상대 비율은 문제별 비율의 기하평균이다. 같은 지도의 문제 간 상관을 고려해 지도 단위 bootstrap 2,000회, seed=20261025의 95% 구간을 사용한다. 성공률은 전체 분모, 길이 비교는 양쪽 모두 유효한 문제의 분모를 명시한다.
- 경로 길이·연산량의 개선/동일/악화 건수와 동시 개선 여부를 남긴다. 실패와 악화 사례도 보존한다.

## 보존과 완료 조건

코드·규약·데이터 해시, 실행 시각·환경·기준 Git 커밋을 manifest에 기록한다. 원시 결과는 새 폴더에 저장하고 기존 `results/main`은 수정하지 않는다. 동일 출력 폴더에 재실행해 덮어쓰지 않는다. 이번 완료 조건은 정확성 검사, 파일럿·본실험·합성 지도 결과, 한국어 해석, 재실행 명령과 사례 그림을 갖추는 것이다.
